# Память проекта «Мэджик Металл»

Краткая рабочая память. Здесь хранятся действующие решения и ссылки на доказательства;
подробные журналы остаются в документах этапов. Не копировать сюда секреты и полные логи.

## Как выбирать решение

Постоянное правило владельца: **в первую очередь проверять массовое применение:
как задачу обычно решают другие сайты и стандартные инструменты. Затем выбирать
из этих подходов простой и надёжный вариант.
Начинать со штатного, проверенного подхода, без лишних усложнений. Собственные
обходные схемы предлагать только после проверки стандартного варианта и доказательства,
почему он не подходит. Если простой вариант решает задачу, на нём остановиться.**

1. Уточнить сломанный пользовательский сценарий и отделить наблюдения от предположений.
2. Составить короткий рейтинг вариантов: ожидаемый эффект, скорость, риск, стоимость
   и расход ресурсов, обратимость. Начать с наиболее эффективного.
3. Использовать ТРИЗ: найти противоречие, проверить имеющиеся ресурсы и простое
   локальное решение. Метод помогает выбрать проверяемый вариант, но не заменяет факты.
4. Реализовать небольшой обратимый шаг, сохраняя работающие части системы.
5. Проверить исходную ошибку и уместный отрицательный случай в реальном сценарии.
6. При доказанном провале записать причину и перейти к следующему варианту.
   Повторять попытку только после значимого изменения условий или диагноза.
7. Обновить фактический результат и следующий шаг. Этап завершён после проверки.

## Как выполнять работу

- Использовать существующий изолированный checkout; новый worktree — по прямому запросу.
- Делегировать агентам независимые задачи с явным владением файлами; избегать
  одновременной правки одного файла и повторения уже выполненных проверок.
- Выбирать MCP и плагины под конкретную задачу; наличие упоминания плагина
  не доказывает доступность его инструментов, авторизации или внешнего сервиса.
- Сохранять утверждённые тексты, композицию, исходные hero и логотип.
  `#about`, его цифры, клиентские логотипы и их стили не изменять.
- Для публичного UI применять typography-scale; для hero проверять 390/1536 px
  при DPR 1.25 и загрузку без JavaScript. Остальные проверки — по уровню из AGENTS.md.
- Сборка, локальный браузер, preview, production и маршрут пользователя — разные
  доказательства. Проверка одного не подтверждает остальные.
- Не объявлять deployment опубликованным, DNS изменённым или Obsidian синхронизированным
  без подтверждения соответствующей операции. Реальные заявки при smoke-проверке не отправлять.

## Текущее знание и ограничения

- На 27 октября 2026 в облачной среде не найден подключённый Obsidian vault или зеркало.
  `OBSIDIAN_API_URL`/`OBSIDIAN_API_KEY` отсутствуют; локальный порт 27124 не принимает
  соединения. Запись в Git не считать записью в Obsidian.
- После добавления сетевых доменов 27 октября `magicmet.ru` стал отвечать HTTP 200.
  После push `3c945bd` живой HTML содержит 18 активных hero-полос; Chromium
  из облака загрузил все файлы. Пользовательский Chrome продолжил показывать пропавшие полосы; 28 октября
  по требованию владельца выбран стандартный picture/AVIF/WebP. Встроенные
  размытые изображения и полосы отменены; смотреть актуальный отчёт hero. Успех в облаке
  не заменяет проверку его соединения.
  Проверка облачного маршрута не доказывает состояние соединения пользователя.
- Исторически крупные ответы обрывались около 20 400 байт. Рабочий обход использовал
  18 адаптивных hero-полос, каждая меньше 15 КБ. Это основание для регрессионного
  сценария, а не доказательство текущей причины на любом подключении.
- Последняя запись архива DNS от 13 октября описывает возврат на `216.198.79.1`
  после выборочного таймаута на `76.76.21.21`. Не менять DNS по более ранней записи
  без новой проверки и сохранённой точки отката.
