# Magic Metal: экономный режим Codex

## Границы задачи

- Работай только с текущим запросом. Не повторяй общий аудит сайта без прямой просьбы.
- Сохраняй утверждённые тексты и компоновку. Каталог остаётся единым; СДТ — обычная категория общего дерева.
- Перед изменением найди существующий компонент и продолжай его дизайн-систему.

## Экономия контекста

- Начинай с `git status`, `rg --files` и точечного `rg -n -C 3`; читай только нужные диапазоны файлов.
- Не выводи в чат содержимое `public/data/*.json`, `private/data/`, `.next/`, бинарных файлов и полные логи. Для них показывай только размер, количество строк, схему, хеш или итог проверки.
- Ограничивай обычный вывод команд 4 000 токенами и сокращай успешные логи до одной строки с результатом.
- Не перечитывай неизменённые файлы и не запускай повторный аудит, если после последней проверки соответствующий код не менялся.
- Используй один основной поток. Параллельные агенты — только для действительно независимых задач и по прямой просьбе пользователя.

## Проверка по уровням

1. Текст, CSS или один компонент: одна профильная проверка изменённого поведения; без полного линтера и сборки.
2. Каталог или данные: только `vitest` для `catalog-structure` и `catalog-search`; не запускать несвязанные API/E2E-тесты.
3. Конфигурация, зависимости или маршруты: профильный тест и TypeScript/build только если изменение может затронуть сборку.
4. Перед публикацией: один полный линтер и одна production-сборка `next build --webpack` на всю пачку изменений.

- Визуально проверяй только изменённый маршрут и изменённые состояния интерфейса.
- Объединяй связанные правки в одну пачку и проверяй её один раз, а не после каждого файла.
- Не повторяй успешный тест, линтер или production-сборку, пока после них не изменился код, который они покрывают.
- Не запускай полный E2E, общий аудит и все тесты репозитория без прямой причины или просьбы пользователя.
- Не сообщай о готовности, пока нужный уровень проверки не прошёл.

## Короткий отчёт

- Сообщай только: что изменено, какие проверки прошли, что осталось и ссылку на опубликованную версию.
- Не включай полные диффы, реестры инструментов и длинные трассировки, если пользователь их не запросил.
