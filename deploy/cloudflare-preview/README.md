## Одноразовый публичный preview

Workflow `.github/workflows/temporary-worker-preview.yml` использует официальный `cf deploy --prebuilt --temporary-account --no-provision`. Он создаёт временный аккаунт, публикует только тестовую версию и не требует заранее подключённого Cloudflare token. CLI в noninteractive-режиме автоматически принимает стандартные Terms/Privacy Cloudflare; аккаунт и ресурсы удаляются, если claim не завершён за 60 минут. Автоматического продления, постоянного хостинга и смены DNS нет. Для постоянного deployment нужен обычный аккаунт.

[Официальные условия](https://developers.cloudflare.com/workers/platform/claim-deployments/). Лимиты temporary assets: 1000 файлов, каждый до 5 MiB. До создания аккаунта helper проверяет лимиты и выключенную SMTP-политику. Актуальная локальная сборка содержит 257 assets, максимум 1 157 072 байта.

CLI выводит секретную claim-ссылку. `deploy-temporary.mjs` захватывает stdout/stderr в приватный файл runner с mode0600; не публикует их в логи/артефакты. В summary идёт только публичный workers.dev URL, настоящий app source и отдельный workflow SHA. Срок — ориентировочный, не серверное подтверждение expiry. Три теста фиктивного CLI проверяют отсутствие утечки при успехе, ошибке и неоднозначных URL; они прошли. Claim-ссылка не записывается в Git/память/Obsidian.

Постоянные credentials не подключать к этому временному workflow: сочетание существующей авторизации с temporary flag не поддерживается. Workflow запускается только в public repo на стандартном runner; artifact/cache storage не используется. На ветке free-ci/sheets-20261105 Vercel auto-deployment отключён.

Локально: `node deploy/cloudflare-preview/prepare.mjs --name=<новая-папка>` создаёт очищенный снимок и ставит закреплённые зависимости. В полученной папке `node_modules/.bin/vite build` и `node_modules/.bin/vite preview --host 127.0.0.1 --port 3032`. Подготовка не делает login/deploy. Первый запуск prepare внутри sandbox остановился на spawnSync git EPERM; штатный запуск с расширенным разрешением прошёл. Root зависимости сохранены; локально повторно использована прежняя закреплённая isolated installation.

## Границы

Публичный preview считается работающим только после успешного deployment и контрольных запросов к фактическому URL. Build и готовый workflow не равны публикации. В temporary runtime нельзя считать подтверждённой нормативную применимость и наличие продукции. SMTP и CMS остаются выключенными; пользователь может проверять выбор параметров и переход к форме, но реальные заявки здесь не отправляются.
