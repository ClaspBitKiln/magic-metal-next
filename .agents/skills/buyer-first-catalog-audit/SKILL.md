# Buyer-first Catalog Audit

Перед действиями прочитай `docs/ai/CATALOG_SWARM_MASTER_PROMPT.md` **полностью** и `docs/PRODUCT_PRINCIPLE_BUYER_FIRST.md`. Это обязательные инструкции workflow.

## Запуск

1. Проверь актуальную `main`, открытые PR и реестр каталога, не перезаписывай существующую работу.
2. Раздели товарные группы между независимыми потоками и выдай каждому критерии, формат записи результата и ссылки на исходники из мастер-промпта.
3. Применяй конкурентные источники только как подтверждение рыночной терминологии и примеров, а не нашего склада. ГОСТы/марки проверяй отдельно.
4. Для каждой карточки сформируй первые 3–5 параметров + марки/исполнение + ГОСТ + прямой запрос, полную таблицу оставь ниже.
5. При подготовке изменений обеспечь ветку/PR, ревью, preview READY, затем production READY. Технически спорные изменения без ревью не публикуй.
6. Сдавай конкретный результат: URL, подтверждённые примеры, ссылки-источники, PR, QA, остающиеся риски.

Если параллельных агентов недоступно, используй отдельные задачи GitHub по группам и двигайся в ограничениях доступных инструментов. Не представляй созданные задачи как уже выполнившихся агентов.

## Постоянные критерии

- Никаких вымышленных комбинаций «размер × марка × ГОСТ × наличие».
- Не смешивай Дн, DN и PN; марки сплавов и классы прочности; номинальный ряд и подтверждённый склад.
- Нет обязательной корзины: готовую спецификацию можно отправить без поиска.
- По всем товарным URL — проверка мобильного UX и корректной заявки.
