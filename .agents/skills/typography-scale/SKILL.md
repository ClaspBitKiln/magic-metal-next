# Контроль типографики Magic Metal

Применяй этот skill при каждой правке публичного UI: страницы, компонента, CSS, таблицы, карточки, формы или текста, меняющего переносы. Это постоянное требование владельца. Для изменений только серверной логики укажи, что типографика не затронута; повторный визуальный аудит не нужен.

## Сначала найди принятую шкалу

1. Прочти `AGENTS.md`. Найди действующий компонент и последние CSS-переопределения, включая media queries и наследование. Не определяй реальный размер по первому совпадению в CSS.
2. Зафиксируй computed styles на изменяемой странице и на существующей компактной странице того же типа: `font-size`, `line-height`, `font-weight`, ширину контейнера. Сохраняй утверждённую иерархию и плотность каталога. Новые элементы привязывай к этому образцу; не создавай отдельную увеличенную шкалу.
3. Если утверждённого образца нет, начни с умеренной шкалы для содержательных страниц: основной текст 16–18 px, таблицы и вторичные подписи 13–16 px, кнопки 14–16 px, h1 28–36 px на телефоне и 36–48 px на desktop, h2 22–28 px на телефоне и 28–36 px на desktop. Это ориентиры для проверки, а не разрешение автоматически заменить существующие размеры. Крупный hero главной оценивай отдельно по утверждённому дизайну.
4. Особенно проверь заголовки от 40 px на телефоне, от 56 px на содержательной desktop-странице и большие h2 в форме заявки. Обоснуй исключение либо предложи локальную правку. Не уменьшай весь сайт общим селектором `h1`, `h2` или `*`.

## Проверка в браузере

- Для затронутых страниц проверь ширины **320, 390 и 1536 px**, штатный масштаб 100%. Запиши computed размеры видимых h1/h2, основного текста, таблиц, кнопок и полей ввода. Измеряй после загрузки шрифта (`document.fonts.ready`), учитывай открытое состояние изменённого подраздела.
- Оцени скриншоты: длинное русское название, ГОСТ, марку стали и размеры. Заголовок не должен вытеснять полезное содержимое без причины, обрезаться или перекрывать кнопки. Не исправляй перенос технического обозначения выдуманным пробелом или изменением данных.
- Проверь **реальный масштаб браузера 200%** на desktop: содержимое и действия остаются доступными, текст не обрезан фиксированной высотой. Если автоматизация не поддерживает browser zoom, явно укажи ограничение; тест узкого viewport или `deviceScaleFactor` не выдавай за проверку масштаба 200%.
- Сравни `scrollWidth` и `clientWidth` документа; случайной горизонтальной прокрутки страницы быть не должно. Широкая нормативная таблица может прокручиваться внутри подписанного контейнера, сохраняя доступность всех столбцов.
- Не делай текст мельче ради устранения overflow. Сначала проверь `min-width: 0`, ширины колонок, переносы и контейнер прокрутки. Не отключай пользовательский zoom. На телефоне поля ввода обычно должны иметь минимум 16 px, чтобы не провоцировать автоматическое увеличение iOS.
- Сохраняй читаемый межстрочный интервал: основной текст обычно 1.4–1.6, заголовки 1.1–1.3. Высота области нажатия кнопки/ссылки не должна уменьшаться вместе со шрифтом; сохраняй принятый минимум 44 px для основных интерактивных элементов.

## Защищённые части и скорость

- **Не изменяй раздел опыта `#about`, его цифры, клиентские логотипы и относящиеся к ним стили.** Указание владельца «опыт не меняй» действует и при унификации типографики. Не добавляй глобальное правило, которое затронет этот раздел через наследование.
- Сохраняй компактный дизайн каталога и нормативные таблицы. Не загружай новый web font, набор начертаний, JS или библиотеку ради размера текста. Используй существующий шрифт и локальные CSS-селекторы.
- Выполняй только нужный уровень проверок из `AGENTS.md`. Не запускай общую сборку после каждого изменения размера. Перед публикацией вся пачка проходит требуемые общие проверки один раз.

## Результат

В отчёте по UI коротко укажи изменённые маршруты, фактические размеры до/после, проверенные ширины, результат zoom и overflow, сохранность `#about`. Не объявляй контроль пройденным по одному CSS-поиску или скриншоту. При отсутствии изменения UI достаточно отметки «типографика не затронута».
