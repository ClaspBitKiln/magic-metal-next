# Программа восстановления и отключения фоновой синхронизации

Запрос владельца: сохранить доступ Remote и заметки; отменить синхронизацию
по расписанию/при входе, записывать результат после каждого этапа с readback.

Актуальный пакет: `docs/downloads/Obsidian-Stage-Recovery-2026-11-08.zip`.
Прежний пакет от 7 ноября сохранён как исторический.
Запуск на авторизованном Windows: распаковать целиком, открыть `START.cmd`.
Самостоятельно пакет из облачной среды на ПК не выполнялся.

Сборка: `python scripts/build_obsidian_stage_recovery.py --out <путь.zip>`.
Сборщик использует только существующие исходники, без секретов и скачиваний.
Архив включает инструкции для этого конкретного запуска, не заменяет полную
стартовую инструкцию проекта и не утверждает работоспособность всех связок.

## Поведение

- Только на `DESKTOP-BNPIVK2`, только известная задача `MagicMetal Catalog Sync`.
- Два ярлыка синхронизации перемещаются из Startup в резервную папку;
  сохранность подтверждается SHA-256. Заметки и старые скрипты сохраняются.
- Задача `MagicMetal Remote Connection`, ярлык Remote и посторонние элементы
  остаются. Идущая синхронизация не прерывается посреди записи.
- Существующий Remote не перезапускается и не дублируется. При отсутствии
  используется ранее подготовленный официальный сценарий восстановления.
- Изменения и диагностика имеют отдельные коды результата. Ошибка после
  частичного выполнения не означает, что предыдущих изменений не было.
- Отчёты локальны: `manual-sync-disable.log` и, при запуске Node,
  `recovery-report.json` в `%LOCALAPPDATA%\MagicMetalObsidianSync`.
  Для JSON проверять `checkedAt`, а не принимать старый файл за новый результат.

## Проверка

`node tests/disable-obsidian-autosync.test.mjs`: 7/7 PASS без пропусков.
Проверены просмотр без изменений, точечное отключение/сохранность Remote,
hash резервных ярлыков, повторный запуск без дублей, ошибки перечисления
и отключения задачи, обнаружение неэффективного отключения, отказ на другом ПК.

Использован PowerShell7/Linux; Task Scheduler имитируется. Файловые операции
реальны во временной папке; единственная платформенная подмена в тестовой
копии — получение пути Startup. Windows/PowerShell5.1 не проверены.
Прежние 13 core и 8 wrapper проверок относятся к неизменённым диагностическим
скриптам; не выдавать их за дополнительные тесты нового START.cmd.
Архив: CRC, SHA-256 каждого файла, совпадение с исходниками и наличие защит
START.cmd проверены. Реальное выполнение CMD на Windows не проверено.

По новому правилу владельца полный старт обновляется только после реальной
проверки требуемых соединений. Текущий чат Windows vault не читал и не писал.
