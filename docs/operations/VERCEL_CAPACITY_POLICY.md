# Постоянный запас Vercel

Источник требования: владелец просит поддерживать свободный объём без ущерба сайту. Бесплатные квоты конечны; очистка не увеличивает тариф и не возвращает уже потраченные запросы/минуты сборки.

## Уже действует

- Автохранение проекта: Preview/CANCELED/ERROR1день, Production14дней, deploymentsToKeep10. Настройки прочитаны, но в этой сессии не менялись.
- В опубликованном source a4878b9 автоматические Preview пропускаются без MAGICMET_BUILD_PREVIEW=1; при известной базе документы не вызывают build. Старые ветки имеют свои старые скрипты — правило не считать глобальным запретом Preview.
- Код сокращения повторных live-аудитов подготовлен в release-ветке; GitHub workflow начнут действовать после включения в main. Main пока2f526c5; не выпускать его без включения листовой пачки.

## Предлагаемый контроллер запаса — ещё не включён

1. Проверять объём ежедневно и после каждой успешной публикации. Оценивать Deployment Storage и Functions Storage отдельно; не складывать их. Работать только по свежим фактическим datapoints, а не queriedAt и не нулевым отсутствующим точкам.
2. Порог начала очистки —70% каждого лимита; целевой объём —50–60%. При лимите10ГБ это7ГБ и5–6ГБ. Порог80% требует приостановить необязательные Preview/полные live-аудиты. Это рабочие пороги политики, не измеренный текущий свободный объём.
3. Всегда сохранять текущую Production, два предыдущих различных успешно опубликованных SHA и явно закреплённые версии. READY и назначение доменов перепроверять перед каждым DELETE. Три произвольных последних deployments не равны трём рабочим откатам.
4. Кандидаты: старые ненужные Preview закрытых/слитых веток с изменениями, включёнными в текущий опубликованный SHA; старые Production за пределами двух откатов. Исходники остаются в Git. Незавершённые сборки и неизвестную историю пропускать.
5. Пользовательские домены и закреплённые/активно согласуемые Preview запрещены к очистке. Служебный alias ветки можно удалять только вместе с явно разрешённой устаревшей Preview; удаление отключает её тестовую ссылку. Исторические detail.alias не подменяют live alias query.
6. Размер партии —до5READY. Перед каждым удалением читать project.targets.production и live aliases. Сохранять журнал намерения и результата; подтверждать GET404. После партии сверять сайт, оба отката и адреса. Дальше ждать свежего замера объёма; при задержке метрик не продолжать бесконтрольно.
7. При ошибке API, изменении текущей Production, новом адресе, отсутствии рабочего отката, устаревшем замере или недостаточной истории — остановка без удаления. Не менять DNS, тариф, проект и базу. Не создавать новые аккаунты как механизм бесконечной квоты.

Периодический контроллер и schedule пока не подключены. Существующий scripts/vercel-cleanup.py — инструмент конкретной ручной пачки с закреплёнными SHA, его нельзя выдавать за готовую общую автоматику. Для внедрения нужен отдельный read-only планировщик с тестами политики, затем ограниченный исполнитель; используемый токен остаётся в секретах, в Git/логи не переносится.


## Реализованный контроль, 6 ноября

Добавлены scripts/vercel-capacity.py и workflow vercel-capacity-report.yml: ежедневный отчёт в 10:17 по Екатеринбургу и после успешной Production. Контроллер только читает API Vercel; сайт не обходит, артефакты в GitHub не загружает. DELETE/PATCH/PUT и создание deployment не поддерживаются; POST разрешён только для запроса метрик.

Защищены текущая Production, два различных рабочих предыдущих SHA и закреплённые версии, включая дубликаты этих SHA. Частичные, нулевые, будущие и старые замеры не объявляются текущим свободным объёмом. Свежесть сравнивается с более поздним временем публикации и завершённой очистки из vercel-capacity-state.json. После следующей очистки состояние надо обновить после проверки результата.

Проверки: 33 профильных теста, разбор 2 YAML, diff --check и реальный read-only запрос API прошли. В отчёте vercel-capacity-latest.json — 23 deployments. Контроллер ничего не удалял.

Новый замер Deployment Storage: 968 404 645 байт (около 0,97 ГБ), 6 ноября 09:00 UTC; он предшествует последней малой очистке. Functions Storage пока содержит только старое значение 10 640 775 745 байт за 5 ноября. Решение — metrics_pending: дальнейшую очистку по этим данным не запускать.

Расписание ещё НЕ активно: workflow не включён в main, наличие защищённого GitHub Secret VERCEL_TOKEN не подтверждено. Секрет среды автоматически в GitHub не переносится. Нужны штатный PR/merge и доступ GitHub; API и авторизованный браузер сейчас отсутствуют, последний push документации остановился из-за авторизации. Новая сборка сайта для контроллера не требуется. Автоматический исполнитель удаления не включён.
