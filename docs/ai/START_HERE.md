# Magic Metal — старт нового аккаунта

Версия 2, 15.11.2026. Часовой пояс: Asia/Yekaterinburg.

Продолжай существующий проект ООО «Мэджик Металл». История чата и авторизации другого аккаунта могут отсутствовать. Сначала восстанови контекст и доступы, затем выполняй актуальное поручение владельца.

## 1. Найди актуальные источники

Репозиторий: https://github.com/ClaspBitKiln/magic-metal-next .
Сайт: https://magicmet.ru .

Прочитай `AGENTS.md`, верхние актуальные записи `MEMORY.md` и [текущую передачу задач](CURRENT_HANDOFF.md). Подробные подключения открывай по необходимости в [справочнике](CONNECTIONS_RUNBOOK.md).

Проверь реальную ветку и открытые PR. Последний известный этап — `feat/free-directory-registration-20261112`, PR169; его состояние нужно сверить. Изменения открытого PR могут отсутствовать в `main`. Сохрани чужие незакоммиченные изменения.

При расхождении источников: текущие указания владельца определяют задачу; фактический сервис и квитанция подтверждают результат; код/конфиг подтверждают реализацию. Более новая заметка не заменяет проверку там, где она необходима. Архивный статус не считать текущим.

## 2. Выбери только нужные подключения

- Каталоги: RDC, рабочий браузер, данные компании; Git и Obsidian для фиксации этапа.
- Изменения сайта: Git, профильные skills, Vercel и проверка затронутого сценария.
- Аналитика: доступ к существующей Метрике; не создавать тестовые визиты.
- Почта/документы/исследование: Gmail, Drive или Firecrawl только по задаче.

Рабочее подключение не переустанавливай. Отсутствующее приложение подключай к существующему аккаунту сервиса. OAuth приложения, секреты облачной среды, браузерный вход и локальный MCP — отдельные доступы.

## 3. Проверь компьютер и правильный браузер

RDC: https://mcp.desktopcommander.app/ . Компьютер `DESKTOP-BNPIVK2`, пользователь `asus`. Получи актуальный device ID через список устройств; исторический ID — в справочнике.

Vault: `C:\Users\asus\Documents\inn-bot`.
Стартовая заметка: `02 Projects\Magic Metal\00 - Инструкция старт - все подключения.md`.

Рабочий профиль Chrome: `%LOCALAPPDATA%\MagicMetalDirectoryBrowser`.
CDP на Windows: `http://127.0.0.1:9223`.
Программы и квитанции: `%LOCALAPPDATA%\MagicMetalDirectoryAutomation`.

Облачный исполнитель и Windows — разные машины. `127.0.0.1` указывает на машину выполнения команды. Обычный Chrome, рабочий профиль и облачный браузер могут быть авторизованы по-разному.

Перед изменением формы проверь URL, компанию, режим «товар компании» и текущие поля. Открытая ссылка или слова «вошёл» не заменяют фактический экран кабинета.

## 4. Подтверди доступ без лишних действий

Для каждого нужного подключения запиши: `проверено`, `настроено, не проверено` или `блокируется`; дату, способ проверки и следующий шаг.

Примеры доказательств: RDC — Online и чтение известной заметки; браузер — нужная компания в кабинете; Git — доступ к нужному репозиторию; API — успешное разрешённое чтение. Запись в Obsidian подтверждается чтением после первой необходимой записи этапа.

Наличие плагина, конфигурации, HTTP 200 или результата задания0 не доказывает весь рабочий сценарий. Проверяй только необходимое. При блокировке продолжай независимую работу; участие владельца проси на конкретном обязательном шаге входа, SMS, CAPTCHA или активации.

## 5. Выполняй работу без дублей

Не создавай заново существующие проекты, счётчики, аккаунты и карточки компании. Не запускай завершённые creator/updater ради проверки доступа.

Один ресурс изменяет один исполнитель. Если владелец или другой агент редактирует ту же форму, согласуй очередность; работай с независимыми файлами или вкладками. Не перезаписывай более новые ручные данные.

Перед внешним сохранением проверь данные и квитанцию предыдущей попытки. Если начат Save, но результат неизвестен, сначала выполни чтение состояния. Тайм-аут или «Result could not be stored» не означает, что операция не выполнилась. Не повторяй мутацию вслепую.

Применяй только профильную проверку. Не повторяй успешные тесты без новых изменений. Агенты нужны для независимых задач; при лимите продолжай по сохранённым материалам основным исполнителем.

## 6. Соблюдай постоянные решения владельца

Все наши товарные предложения — RUB. В описании RUB и справочный USD в скобках с датой курса. Цена относится к обозначенному базовому SKU; диапазон размеров и марок не означает наличие каждой комбинации.

Размещения — правдивые, с соблюдением правил площадки и проверки экспорта. Бесплатные действия в согласованной задаче разрешены; это не разрешение на платные услуги, спам или обход защиты. Юридический адрес и место приёма клиентов не смешивать.

Секреты брать из разрешённых защищённых настроек, не печатать в чате, Git и Obsidian. Не извлекать cookies. Не менять DNS, тарифы, инфраструктуру или удалять данные ради самого старта.

Для правок сайта читать соответствующие skills; сохранять утверждённый дизайн и ограничения проекта. MATBOOK, CMS и Beget/inn-bot не включать в работу без актуальной задачи.

## 7. Закрой этап и передай результат

Различай: подготовлено → сохранение начато → принято/на модерации → опубликовано и проверено. Коммит, push, merge и production — отдельные события.

Обнови текущую передачу задач, добавь короткую запись в MEMORY, сохрани итог и инструкцию в Obsidian. Перед заменой инструкции сделай резервную копию; после записи проверь содержимое или SHA256. Проверь push отдельно. Не объявляй недоступную синхронизацию выполненной.

Передавай: что сделано, доказательство/ID/ссылку, что осталось, точное место продолжения и одно следующее действие. Текущие статусы храни в CURRENT_HANDOFF, детали подключения — в CONNECTIONS_RUNBOOK; не размножай их по всем документам.

Первое сообщение владельцу — краткий статус нужных доступов и конкретное начатое действие. Не обещай «всё работает» по одной найденной конфигурации.
