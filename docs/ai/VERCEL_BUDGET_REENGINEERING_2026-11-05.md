## REA / ТРИЗ: изменить процесс

Противоречие: частые правки и проверки полезны, но каждая удалённая версия и повторный live-аудит расходуют ограниченные ресурсы. Разделяем разработку и доставку: полная проверка в GitHub на localhost → PR → одна Production-публикация → одна автоматическая группа браузерных проверок и Lighthouse. Широкие специальные аудиты доступны вручную.

Подготовлена отдельная ветка fix/vercel-budget-20261105 от main 2f526c5. Выпуск листов сохранён отдельно в release/sheets-20261105; не потерять его при объединении веток.

Изменения:

1. Автоматические Preview пропускаются через Ignore Build Step; явное MAGICMET_BUILD_PREVIEW=1 возвращает обычную проверку изменений для Preview. Рабочая бюджетная ветка дополнительно отключена точным правилом vercel.json. Production сохраняется.
2. Сборка сравнивает весь диапазон от VERCEL_GIT_PREVIOUS_SHA. Нет достоверной базы → сборка выполняется. Старый HEAD^ мог скрыть исходники, когда последний коммит менял только документацию.
3. MEMORY.md и .agents исключены из причины сборки вместе с прежними docs/tests/QA. Изменения исходников и конфигурации не скрываются.
4. Production browser QA больше не дублируется событием push. Локальные PR-проверки и Chromium/Firefox после успешной Production остаются; checkout использует deployment.sha.
5. Site QA, полный каталог и специальный hero-аудит запускаются вручную. Тесты и проверки не удалены. Lighthouse после deployment сохранён.

Проверкой кода установлены повторные обходы: Site QA делает 3N+30 браузерных переходов и N+1 HTTP-запросов для N маршрутов sitemap, без учёта ресурсов. Причина всех 997 782 запросов не установлена: для этого нужны журналы. Не приписывать весь трафик тестам или ботам без доказательств.
