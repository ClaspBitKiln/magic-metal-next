# Рабочая система проекта

## Действующие правила и ответственность

Начинать с [MEMORY.md](../../MEMORY.md) и [AGENTS.md](../../AGENTS.md).
Память содержит решения и ссылки, а не копии журналов. ТРИЗ используется для
выбора простого проверяемого решения: сформулировать противоречие, оценить
варианты по эффекту, риску, времени, ресурсам и обратимости, проверить лучший.
После доказанного провала перейти к следующему варианту с новой диагностикой.

Основной агент отвечает за общий результат. Специалисты получают независимые
задачи и явное владение файлами. Не повторять успешные проверки без изменения
покрываемого кода. Подключать инструмент ради конкретной операции, не ради
количества плагинов.

## Проверка среды

```bash
node scripts/workflow-doctor.mjs --json
node scripts/workflow-doctor.mjs --network --json
```

Doctor не устанавливает пакеты, не запускает службы, не меняет настройки и не
печатает значения переменных. Код 0 — проверки прошли; 1 — локальный блокер;
2 — неверные аргументы; 3 — сетевой блокер. Опциональные неподключённые сервисы
не выдаются за работающие. Доступность MCP проверяется агентом по текущему
каталогу инструментов: shell не может установить её достоверно.

## Разработка и проверки

- Зависимости: `npm ci --cache /workspace/.npm-cache --no-audit --no-fund`.
- База: `docker compose up -d postgres`, затем `docker compose exec -T postgres pg_isready -U postgres -d magicmet`.
- Разработка: `npm run dev`; production: `npm run build`, затем `npm run start`.
- Профильные тесты по задаче; при проверке всего проекта — `npm run test:int` и `npx tsc --noEmit`.
- Браузерные тесты: `npm run test:e2e -- --workers=2`. Для системного Chromium
  задать `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium`; иначе установить
  браузер штатным `npx playwright install chromium`. BASE_URL по умолчанию локальный.
- Проверка опубликованной версии: `BASE_URL=https://magicmet.ru npx playwright test --config=playwright.production.config.ts --project=chromium`.
- Полный аудит локального сайта по запросу: `QA_BASE_URL=http://127.0.0.1:3000 npm run qa:site`.

Перед публикацией один полный линтер и webpack-сборка конечной пачки.
Публичный режим сборки проекта может пропускать проверку типов — отдельно
фиксировать результат `tsc`. Не считать нулевой тестовый прогон доказательством.
Админские тесты используют отдельного локального пользователя и последовательный
seed/cleanup; реальные заявки и интеграционные уведомления не отправлять.

## Публикация и обратная связь

1. Проверить конкретный сценарий, отрицательный случай, desktop/mobile и отсутствие JS, когда это важно.
2. Сохранить код и проверенные изменения в Git; не включать вложения или секреты.
3. Проверить Vercel deployment и фактическую изменённую страницу; push не является подтверждением публикации.
4. Для hero проверить одну чёткую responsive AVIF/WebP-фотографию, совпадение preload/srcset/sizes, один hero-запрос и HTML gzip меньше 15 КБ.
5. Итог хранить в одном датированном отчёте, в MEMORY.md оставить ссылку. В Obsidian заявлять синхронизацию только после повторного чтения.

Если подключение отсутствует, завершить независимую работу и указать точную
недостающую операцию. Не дублировать токены и не обходить сетевую политику.
