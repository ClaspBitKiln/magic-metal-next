# Отчёт посещаемости через API Яндекс Метрики

`scripts/metrika-report.mjs` выполняет только GET к `https://api-metrika.yandex.net`. MCP, новые зависимости, изменения сайта и доступ на запись не нужны. OAuth-токен передаётся только заголовком запроса; скрипт не выводит его или тело ошибки API.

Нужен OAuth-токен аккаунта с доступом к нужному счётчику и разрешением `metrika:read`. Сохраните его в защищённой переменной `YANDEX_METRIKA_TOKEN` среды, а не в командной строке, Git или публичной переменной `NEXT_PUBLIC_*`.

```sh
node scripts/metrika-report.mjs --list-counters
node scripts/metrika-report.mjs --counter 12345678 --days 28 --out /workspace/.cloud/magic-metal/analytics/report.json
node scripts/metrika-report.mjs --counter 12345678 --date1 2026-09-19 --date2 2026-10-16 --out /workspace/.cloud/magic-metal/analytics/report.json
node --test scripts/metrika-report.test.mjs
```

Если сетевой доступ Node в облаке требует настроенного прокси, используйте существующую переменную `NODE_USE_ENV_PROXY=1`; TLS-проверка не отключается.

Без `--out` выводится краткая сводка: посетители, визиты, просмотры, отказы, глубина и средняя длительность, сравнение равных периодов, признаки выборки и наличие цели `request_sent`. Полный JSON дополнительно содержит источники, устройства, посадочные страницы и зарегистрированные цели. Для разбивок берётся не более 50 строк каждого периода, общие итоги API сохраняются отдельно. Доля изменения при нулевой базе — `null`, а не бесконечный рост. В отказах абсолютное изменение означает процентные пункты.

По умолчанию используются относительные даты API `28daysAgo` → `yesterday` и `56daysAgo` → `29daysAgo`, без незавершённого сегодняшнего дня и без преобразования по часовому поясу облачной машины. Метаданные часового пояса счётчика сохраняются в отчёте. При явных датах скрипт проверяет завершённость дня, если API вернул `time_zone_name`; если поле отсутствует, оператору нужно проверить это самостоятельно. В JSON записываются и запрошенные диапазоны, и разрешённые API даты, если они возвращены в `query`.

Запрашивается `accuracy=full`, но это не обещание отсутствия семплирования: проверяйте `sampled`, `sample_share`, `sample_size`, `sample_space`. Поле задержки данных сохраняется только если API его вернул; отсутствие поля не доказывает актуальность. Ошибки отдельных разбивок/целей обозначаются `unavailable`, без подмены нулями. Если `ym:s:startURLPath` недоступен счётчику/API, разбивка посадочных будет помечена недоступной; небезопасный автоматический переход на полные URL не делается. Перед записью посадочные дополнительно очищаются от query/fragment/доступов. Условия целей и их URL не запрашиваются в статистический отчёт и не сохраняются.

Отчёт не меняет фильтрацию роботов и не приписывает ей выдуманное значение: отдельный роботный сегмент здесь не запрашивается. Посетители — идентифицируемые Метрикой браузеры/устройства, а не точное число людей. `request_sent` обозначает событие формы; спам и принятый запрос без сделки не являются продажей. Историю до установки счётчика API восстановить не может. Сравнение недавно установленного счётчика с предыдущим пустым периодом нельзя трактовать как рост бизнеса.

API используется напрямую по документируемым endpoint: `/management/v1/counters`, `/management/v1/counter/{id}`, `/management/v1/counter/{id}/goals`, `/stat/v1/data`. Официальные справочники: <https://yandex.ru/dev/metrika/ru/stat/>, <https://yandex.ru/dev/metrika/ru/management/>. Онлайн-чтение документации из текущего облака было недоступно из-за сетевого ограничения; реальную доступность полей и запросов необходимо подтвердить запуском с авторизованным счётчиком. Офлайн-тесты проверяют календарные границы, равенство периодов и удаление чувствительных частей URL; не заменяют интеграционный API-тест.
