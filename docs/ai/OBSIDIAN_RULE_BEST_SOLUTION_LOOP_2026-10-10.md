# Правило работы: сначала самый эффективный вариант

Дата фиксации: 2026-10-10
Статус: обязательное правило для проекта «Сайт» и следующих технических задач.

## Алгоритм

1. Сначала точно определить проблему и собрать проверяемые факты.
2. Составить короткий рейтинг решений по пяти критериям:
   - ожидаемый результат;
   - скорость реализации;
   - риск поломки;
   - стоимость и расход ресурсов;
   - обратимость.
3. Выбрать самый эффективный вариант №1.
4. Реализовать его изолированно, не затрагивая работающие системы без необходимости.
5. Проверить полный реальный сценарий, а не только сборку или отдельный тест.
6. Если вариант не решил проблему:
   - зафиксировать доказанную причину;
   - не повторять тот же путь;
   - перейти к следующему варианту рейтинга.
7. После каждого этапа обновлять фактический план и запись в Obsidian.
8. Считать этап завершённым только после проверки результата.

## Применение к проблеме изображений сайта

### Факты

- Яндекс Браузер и Firefox загружали HTML и CSS.
- Статические изображения зависали: логотип приходил частично, hero-фото отсутствовало.
- Следовательно, первая сломанная граница: доставка файлов /images/**.

### Критический пересмотр

PR #57 изменил утверждённый дизайн текстовой заменой логотипа и схематичным SVG вместо hero. Это решение отклонено и отменено PR #58. Эталоном признан preview `restore-approved-design`: оригинальный логотип, фотография с производством, трубами и автомобилем, сентябрьская типографика и компоновка.

### Доказанная причина остаточного дефекта production

После отмены PR #57 production продолжал запрашивать `/site.css?v=20261005`, который кешируется на год как `immutable`. Браузер мог совместить новый HTML со старой таблицей стилей. Наблюдаемое доказательство: изображение логотипа было загружено (`naturalWidth = 147`), но старый CSS вычислял ширину контейнера и изображения как `0`.

### Выбранное решение

1. Не менять утверждённый дизайн и его ассеты.
2. Обновить версию URL полного CSS, принудительно отделив новый дизайн от старого кеша.
3. Исправить невалидное мобильное свойство `inset-bottom` на `bottom`.
4. Проверить размер логотипа, hero, desktop/mobile и production после развёртывания.

## Автономное решение без доступа к DNS — 2026-10-12

### Новое доказательство

- Windows super-test проверил 22 фактических ресурса production.
- Через `216.198.79.1` стабильно обрываются не только hero-файлы, но и любой крупный ответ: `site.css` и несколько Next.js chunks останавливаются примерно на 20 400 байтах.
- HTML, логотип и другие ответы меньше порога загружаются за 0,23–0,44 с.
- Следовательно, исправление только hero не устраняет первопричину зависания страницы.

### Реализованный обход

1. Корень `/` отдаёт самостоятельный статический HTML напрямую, без клиентских chunks Next.js и без внешнего CSS.
2. Утверждённые сентябрьские hero, логотип, тексты, цвета и компоновка сохранены.
3. Hero разделён на 18 адаптивных WebP-полос для каждого разрешения `640`, `1024`, `1440`; крупнейший ответ — 11 428 байт.
4. Главная весит 14 508 байт без сжатия и 5 252 байта в gzip; единственный собственный JS-файл весит 1 811 байт.
5. Форма заявки использует компактный JavaScript и прежний `/api/request`; при отключённом JavaScript остаются телефон, email и всё содержимое страницы.
6. Остальные маршруты и старый дизайн не удалены; изменение изолировано на главной и обратимо.

### Контроль качества

- `npm run lint` — успешно.
- production build — успешно, все 140 существующих маршрутов собраны.
- 54 из 54 hero-ресурсов: HTTP 200, WebP, каждый меньше 15 000 байт.
- Сборка плиток имеет размер 1440×810; средняя абсолютная разница с утверждённым исходником — 1,84 из 255 на цветовой канал, визуальных швов не обнаружено.
- PR-CI теперь запускает Chromium и Firefox против кода самой ветки на локальном production server, а не против старого сайта.

Смена DNS на `76.76.21.21` остаётся правильным долгосрочным исправлением маршрута, но больше не требуется для загрузки главной страницы.

## Этап 2026-10-13 — стабилизация production QA

### Проверенный production-сценарий

- Главная `https://magicmet.ru/` полностью загружается в браузере.
- На главной нет внешней таблицы стилей и Next.js chunks; используется один компактный `home.js`.
- Все изображения декодированы, отсутствующих изображений не найдено.
- Пустая форма заявки остаётся невалидной до согласия на обработку данных; реальная заявка при smoke-проверке не отправлялась.
- Утверждённый сентябрьский дизайн и текст `100 000+ тн` сохранены.

### Причина отмены Site QA

Workflow одновременно запускался по `push main` и по `deployment_status`, а общий concurrency-group с `cancel-in-progress: true` отменял соседний запуск. Это гонка событий CI, а не падение сайта.

### Реализованное решение

- Убран дублирующий запуск по `push main`.
- Автоматическая проверка выполняется только после успешного production deployment Vercel или вручную.
- Concurrency разделён по окружениям, чтобы preview-события не отменяли production-проверку.
- Production QA направлен на канонический адрес `https://magicmet.ru`, которым пользуются клиенты.

### Следующий подтверждённый узкий участок

`/spravochnik-gost` загружается, но использует внешнюю таблицу стилей и девять Next.js chunks. Для пользователей на проблемном маршруте до Vercel это менее устойчиво, чем статическая главная. Следующий этап — облегчить справочник без изменения утверждённого дизайна главной.


## Инцидент 2026-10-13 — выборочная недоступность Vercel из России

### Доказанные факты

- Production deployment и автоматический браузерный тест Chromium/Firefox завершились успешно.
- Google DNS и Cloudflare DNS возвращают A-запись `76.76.21.21` с TTL 600 секунд.
- Независимый Globalping-тест из пяти российских узлов дал четыре успешных ответа HTTP 200 (71–872 мс) и один полный TCP timeout 15 секунд у московской сети Mediasoft ekspert.
- Следовательно, сайт и DNS исправны, но маршрут до Vercel доступен не у всех российских провайдеров.
- Текущая статическая главная также полностью проверена через прежний адрес `216.198.79.1`: HTML, `home.js`, логотип, hero-плитка и эмблема Роснефти получены целиком с HTTP 200. После облегчения главной критические ответы укладываются в безопасный размер.

### Рейтинг решений

1. Краткосрочно и обратимо: вернуть A-запись на `216.198.79.1`, поскольку новая облегчённая главная больше не содержит крупных критических ответов.
2. Устойчиво: разместить статическую главную на российском хостинге, Vercel оставить для API и отката.
3. Неэффективно: продолжать менять дизайн, браузерный CSS или количество страниц — TCP timeout происходит до получения сайта.

### Блокер управления DNS

Безопасный вход в SpaceWeb был выполнен через credential handoff, но SpaceWeb вернул `Неверный логин или пароль`. DNS не изменялся. Для следующего действия нужен действующий доступ к SpaceWeb либо отдельный DNS API-токен; перебор паролей не выполняется.
