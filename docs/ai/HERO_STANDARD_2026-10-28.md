# Hero: стандартная доставка изображения

Актуальный подход по требованию владельца: обычный `<picture>`, AVIF с WebP
fallback по поддержке формата, responsive srcset/sizes и один приоритетный preload.
Без встроенных фотографий, полос и скриптов дозагрузки. При сетевом отказе
фотография может отсутствовать: подмена формата не исправляет транспорт.

AVIF quality50, effort6:640px19488Б,1024px40908Б,1440px73884Б. Исходные
WebP сохранены. Файл1440AVIF на31% меньше107110Б WebP. Детали логотипа,
решётки автомобиля и труб осмотрены при1:1; размытой миниатюры нет.

Для экранов до700px применяется стандартная art direction через source media:
мобильный AVIF840×810 —54405Б (−26,4%), WebP fallback91460Б. Кадр вырезан из
того же оригинала без потери видимых пикселей: left396,width840,height810;
396=.66×(1440−840), поэтому object-position66% сохраняет прежнюю композицию.
CSS меняет только размеры контейнера изображения на mobile; текст и #about
не затрагиваются. Preload media взаимоисключающие: загружается один файл.

Генерация: `node scripts/generate-hero-images.mjs`. Новое содержимое ассетов
требует нового URL/version для immutable-кэша. AVIF preload srcset/sizes совпадает
с picture: нет двойной загрузки AVIF и WebP. WebP fallback работает при
неподдерживаемом AVIF; он не является retry при сетевом отказе AVIF.

Локальный mobile Lighthouse2прогона:97/100, LCP1,579–1,586с, CLS0,
