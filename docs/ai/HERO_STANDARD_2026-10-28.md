# Hero: стандартная доставка изображения

Актуальный подход по требованию владельца: обычный `<picture>`, AVIF с WebP
fallback по поддержке формата, responsive srcset/sizes и один приоритетный preload.
Без встроенных фотографий, полос и скриптов дозагрузки. При сетевом отказе
фотография может отсутствовать: подмена формата не исправляет транспорт.

AVIF quality50, effort6:640px19488Б,1024px40908Б,1440px73884Б. Исходные
WebP сохранены. Файл1440AVIF на31% меньше107110Б WebP. Детали логотипа,
решётки автомобиля и труб осмотрены при1:1; размытой миниатюры нет.

Мобильный canvas из-за исходной cover-композиции шире viewport (~1250px).
Поэтому sizes учитывает фактическую область изображения; при390px выбирается
1440AVIF, а не растягивается640px. Тексты, кадрирование и #about сохранены.

Генерация: `node scripts/generate-hero-images.mjs`. Новое содержимое ассетов
требует нового URL/version для immutable-кэша. AVIF preload srcset/sizes совпадает
с picture: нет двойной загрузки AVIF и WebP. WebP fallback работает при
неподдерживаемом AVIF; он не является retry при сетевом отказе AVIF.

Локальный mobile Lighthouse2прогона:97/100, LCP1,579–1,586с, CLS0,
TBT172/2мс. Результат97 сохранён. Это лабораторный замер, не полевая скорость.
Встроенная размытая версия была быстрее по LCP, но отклонена владельцем.
HTML с аналитикой12889Б gzip, hero73884Б за один запрос.

Webpack build и ESLint прошли. Chromium smoke:9проверок сразу прошли,
одна mobile-проверка имела ошибочное сравнение density-corrected naturalWidth
с encoded-пикселями; после исправления теста она прошла отдельно. Один
production-only canonical сценарий пропущен локально. Точные размеры файлов
и полнота контейнеров проверяются отдельно. Настоящие320/390/1536px:
AVIF декодирован, один hero-запрос, горизонтальное переполнение0.

Проверка опубликованной версии запускается `.github/workflows/live-hero-check.yml`;
доказательства сохраняются в ветке `codex/live-hero-check`. Только отчёт с
sourceCommit текущей версии подтверждает новую публикацию. История экспериментов:
