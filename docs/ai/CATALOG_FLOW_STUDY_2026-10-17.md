# Как проверять логику отраслевых каталогов: 17.10.2026

Цель: сократить путь от технических требований до корректной заявки,
сохраняя скорость, российские нормативные данные и отсутствие корзины.
Нельзя объявить каталог «лучшим в РФ» без сравнительного измерения задач
закупщика, ошибок подбора и результатов реальных посетителей.

## Воспроизводимый способ исследования

1. Один сценарий на всех сайтах: найти изделие с заданным размером,
   проверить марку/стандарт и открыть заявку. Отдельно — отсутствующее
   сочетание, смена фильтра, возврат назад, вход с телефона и отключённый JS.
2. Записывать начальный URL, видимые подписи, действие и конечный URL;
   после клика проверять сам результат, а не только изменение адреса.
   Для фильтра — совпадение всех выбранных параметров в одной позиции.
3. Сохранять DOM/снимок и, если доступно, только метаданные GET-запросов.
   Различать серверную навигацию, клиентскую фильтрацию загруженных строк
   и запрос к API. Видимый селектор не доказывает работу фильтра.
4. Считать переходы до результата, обязательные поля и число сетевых
   запросов; отдельно отмечать мобильную прокрутку и пустое состояние.
   Формы не отправлять, корзины не менять, личные данные не вводить.
5. Использовать Firecrawl scrape actions/executeJavascript для чтения
   DOM и безопасных кликов. При недоступности сервиса — браузер с обычной
   проверкой TLS; не обходить вход, CAPTCHA или ограничения доступа.
   Поисковый сниппет годится для записи обозначения, но не доказывает UX.
6. Переносить один полезный приём в существующий компонент и проверять
   его на наших данных. Затем сравнивать HTML/JS и мобильную отрисовку.
   Не переносить цены/остатки и не считать коммерческую карточку нормативным
   подтверждением размера по ГОСТ.

## Российские сайты: фактические действия

Проверка выполнена Firecrawl v2 с браузерными actions, не по сниппетам.

| Сайт | Действие | Подтверждённый результат |
| --- | --- | --- |
| Metal100 | Категория листа → клик «6» → карточка позиции | URL /prodazha/Sortovoj-prokat/List-g-k/6 и h1 подтверждают толщину 6 мм; открыта позиция с маркой 3сп5, возвратом к списку и хлебными крошками |
| E-Metall | Категория /list/, поиск толщины «6», открытие «Заявка в 1 клик» | Поиск вариантов показывает 6, 60, 6,5 и 0,6; в открытой форме контекст изделия «Лист стальной горячекатаный 10 мм 1500х6000 ст3» и поставщик |

У Metal100 толщины — обычные GET-ссылки; полезен прямой якорь «Вес / Размеры».
У E-Metall отдельно представлены толщина, размер, марка и стандарт, есть
сброс. Поиск «6» — поиск вариантов по подстроке, не применение точного фильтра;
совпадение с 60 не объявляется ошибкой сайта. Точный выбор должен быть
отдельным действием. Мобильный DOM E-Metall: innerWidth=scrollWidth=360;
высота удалённого движка 100000, поэтому это не полноценная визуальная
проверка реального экрана по высоте.

Подтверждено открытие формы и перенос контекста, не доставка заявки.
Совместное применение двух фильтров и пустая выдача конкурентов не
подтверждены: первые селекторы checkbox не нашли элемент. Это ограничение
исследования, не доказательство неисправности чужого сайта. Скорость
конкурентов не измерялась. Полный путь на mc.ru недоступен через использованный
Firecrawl scrape; прежние примеры обозначений mc.ru остаются индексными.

Для нас выбраны простой прямой доступ к размерам, разделение параметров,
точная проверка сочетаний и перенос контекста заявки. Карты, корзина,
подписки, цены и складские остатки агрегаторов не перенесены.

## GitHub: проверены исходники

| Проект и версия | Прочитанные файлы | Применимый приём |
| --- | --- | --- |
| [TanStack Table v8.21.3](https://github.com/TanStack/table/tree/v8.21.3/packages/table-core/src) | filterFns.ts, utils/getFilteredRowModel.ts, utils/getFacetedRowModel.ts; пример filters-faceted | Точное сравнение; AND между атрибутами; фасет учитывает остальные фильтры, исключая собственный |
| [htmx v2.0.7](https://github.com/bigskysoftware/htmx/tree/v2.0.7/www/content) | attributes/hx-boost.md, hx-push-url.md, examples/active-search.md | Обычная ссылка/GET-форма как основа; URL, история и возврат; запросы не на каждый ввод |
| [W3C APG, 0f765e4](https://github.com/w3c/aria-practices/tree/0f765e4dc33e966026114ac12a8380db1de3b787/content/patterns/table) | table-pattern.html, examples/sortable-table.html | Нативная table/caption/th, подписанные внешние фильтры; button/aria-sort только при нужной сортировке |

Из этих проектов берём принципы. Новые TanStack/htmx-зависимости и ARIA-grid
не добавлены. Наша таблица не должна превращаться в электронную таблицу
со множеством фокусируемых ячеек. Простой размер 20 не совпадает с 120;
3 не совпадает с 3,5. Размеры проверяются внутри исходного сочетания.

Состояние фильтра в URL реализовано следующим отдельным шагом:
CATALOG_SIZE_URL_STATE_2026-10-17.md. Выбор восстанавливается после
перезагрузки и при переходах назад/вперёд; страницы остаются статическими.
Без JS доступен полный ряд, серверная фильтрация по URL не заявляется.
