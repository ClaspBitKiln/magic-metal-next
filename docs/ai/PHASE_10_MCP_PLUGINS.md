# Phase 10 — MCP / Plugins

## Цель
Подключать только те инструменты, которые реально нужны Procurement Engine и агентам.

## Минимальный набор

| Инструмент | Статус | Назначение | Доступ |
|---|---|---|---|
| GitHub | active | код и документация | read / write |
| Obsidian Gateway | planned | база знаний | search / read / append |
| Firecrawl | planned | публичные источники | search / read |
| Activepieces | planned | автоматизация | trigger |

## Правила
- Каждый инструмент получает только необходимый доступ.
- MCP не получает права на клиентские данные сверх необходимого.
- Поставщики, закупочные цены и внутренняя экономика не передаются в клиентский слой.
- Никаких новых MCP-сервисов без реальной задачи.
- MCP используется как транспорт доступа к инструментам, а не как отдельный бизнес-движок.

## Результат этапа
Есть единый простой реестр подключений и понятные права доступа. Реальные подключения выполняются отдельно, когда соответствующий инструмент готов к использованию.
