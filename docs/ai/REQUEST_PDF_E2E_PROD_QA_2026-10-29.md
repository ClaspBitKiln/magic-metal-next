## Подтверждено реальным тестом
- **Ровно одна** тестовая multipart-заявка в production `POST https://magicmet.ru/api/request` с синтетическим PDF 609 байт, помечена «ТЕСТ — не обрабатывать».
- HTTP 200, `ok:true`, `emailDelivered:true`, `crmDelivered:false`, `id:null`.
- Пользователь предоставил скриншот Yandex 360 почты `m1@magicmet.ru`: тестовое письмо в папке входящих, вложение `MM-QA-20261029-PDF-01.pdf` видно; тело содержит соответствующий номер и контекст.
- Это подтверждает **приём API → успешную SMTP-передачу → получение письма и наличие вложения во входящем сообщении**.
- **Не проверено**: открывается ли файл в почте без повреждений; сохранены ли заявка/вложение в Payload CMS (ID null).

## Причина `id:null` точно определена

Лог Vercel production в **2026-10-29T15:59:53.811Z**:
```
{"level":"error","message":"Request persistence failed","route":"/api/request","error":"Обязательная переменная окружения PAYLOAD_SECRET не задана"}
```

`src/payload.config.ts` требует **и** `PAYLOAD_SECRET`, **и** `DATABASE_URL` для PostgreSQL. Проверены имена Vercel production env, **без получения секретных значений**: там только `SMTP_HOST`, `SMTP_PORT`, `SMTP_SECURE`, `SMTP_USER`, `SMTP_PASSWORD`, `REQUEST_TO_EMAIL`. Ни `PAYLOAD_SECRET`, ни `DATABASE_URL` нет. Значит **база заявок сейчас не подключена**, и запись в CMS не функционирует.

Важно: не путать «принято к отправке по почте» с «сохранено в базе». На SMTP-маршрут с вложением это не влияет.

## Минимальный безопасный путь исправления
1. Выбрать выделенный управляемый PostgreSQL для проекта и создать базу/пользователя с ограниченными правами и резервным копированием. **Нельзя** использовать случайную общую базу и нельзя подставлять URL из других проектов.
2. В Vercel production задать `DATABASE_URL` как секрет подключения к этой базе, `PAYLOAD_SECRET` — новый сильный секрет приложения. Не публиковать их в GitHub, чате, Obsidian или логах.
3. Проверить миграции/создание таблиц Payload и подключение в тестовом окружении до запуска production. Для файлов учесть: локальный диск серверной функции Vercel **не является постоянным файловым хранилищем**. Нужно объектное хранилище/адаптер для `request-files` с приватными правами и бэкапами, либо не обещать хранение вложений в CMS.
4. После конфигурации — отдельный авторизованный тест **одной** заявки с вложением, проверка `id != null`, чтения записи в CMS, скачивания файла, а также доставки почты. Не повторять прежний тест без необходимости.
