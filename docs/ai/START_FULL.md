### 5. Выполняй работу без дублей

Не создавай заново существующие проекты, счётчики, аккаунты и карточки компании. Не запускай завершённые creator/updater ради проверки доступа.

Перед внешним сохранением проверь данные и квитанцию предыдущей попытки. Если начат Save, но результат неизвестен, сначала выполни чтение состояния. Тайм-аут или «Result could not be stored» не означает, что операция не выполнилась. Не повторяй мутацию вслепую.

Применяй только профильную проверку. Не повторяй успешные тесты без новых изменений. Агенты нужны для независимых задач; при лимите продолжай по сохранённым материалам основным исполнителем.

Секреты брать из разрешённых защищённых настроек, не печатать в чате, Git и Obsidian. Не извлекать cookies. Не менять DNS, тарифы, инфраструктуру или удалять данные ради самого старта.

### 7. Закрой этап и передай результат

Различай: подготовлено → сохранение начато → принято/на модерации → опубликовано и проверено. Коммит, push, merge и production — отдельные события.

Обнови текущую передачу задач, добавь короткую запись в MEMORY, сохрани итог и инструкцию в Obsidian. Перед заменой инструкции сделай резервную копию; после записи проверь содержимое или SHA256. Проверь push отдельно. Не объявляй недоступную синхронизацию выполненной.

Передавай: что сделано, доказательство/ID/ссылку, что осталось, точное место продолжения и одно следующее действие. Текущие статусы храни в CURRENT_HANDOFF, детали подключения — в CONNECTIONS_RUNBOOK; не размножай их по всем документам.

### Установка на другом компьютере

Новый аккаунт ИИ на прежнем Windows не требует переустановки программ. Если меняется сам компьютер, сначала восстановить данные и установить необходимое:
- Node.js: https://nodejs.org/ ; проверить `node --version`, `npm --version`, `npx --version`;
- Chrome: https://www.google.com/chrome/ ; создать рабочий профиль под нового пользователя, не переносить чужие cookies;
- Obsidian: https://obsidian.md/ ; восстановить исходный vault из проверенной копии, открыть его, проверить `.obsidian` и плагины;
- Git: https://git-scm.com/ ; для разработки также проверить доступ к нужному репозиторию;
- Python — только если нужен конкретный вспомогательный скрипт, выбрать реально установленную рабочую версию.

После ручного успешного запуска RDC восстановить автозапуск под действительные пути. На новом Windows не переносить вслепую путь кэша _npx, device.json, DPAPI или конфиг другого пользователя. Проверить подключение после выхода/входа и перезагрузки; при переносе vault убедиться, что это прежние заметки, а не пустая новая папка.

Если приложение ИИ не показывает RDC-инструменты, найти/подключить Remote Desktop Commander в приложениях данного аккаунта и авторизовать существующий аккаунт сервиса. Если список устройств пуст, проверить аккаунт/разрешения и включённый компьютер; отсутствие устройства не является само по себе поводом удалить прежнюю привязку. ЭкспортныйНДС0% и СТ-1 применяются при соблюдении законных условий. Российский склад не доказывает российское происхождение. Проверить точную форму/марку/HS10/НТД и актуальные ограничения на дату сделки. Предварительная проверка стандартного SKU не заменяет документы партии, проверку покупателя/конечного применения и лицензирования по 183-ФЗ ст.20/24. Обычные позиции7307/прокат не дают автоматического допуска любой специальной военной/ядерной детали.

Поддержке Prom уже направлялся вопрос о противоречии бесплатного лимита; не дублировать письмо из-за нового аккаунта. Отсутствие оплаты на форме не доказывает бессрочную бесплатность всех услуг. Платные опции не включать, CAPTCHA/SMS проходить штатно.
