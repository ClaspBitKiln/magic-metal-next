# Бесплатные размещения: рабочий порядок

Область: Magic Metal, РФ и доступные для компании РФ каталоги СНГ. Пользователь
разрешил выполнение бесплатных регистраций. Платные размещения и новые подписки
в эту очередь не входят. Порядок для агента:
[free-directory-acquisition](../../.agents/skills/free-directory-acquisition/SKILL.md).

## Продолжить существующую очередь

Сначала сверить `MEMORY.md`, GitHub main/PR, текущий Windows/RDC и последний итог
Obsidian. Не считать старый отказ сети или старое состояние входа текущим.

```bash
node scripts/growth/acquisition.mjs platforms
node scripts/growth/acquisition.mjs plan --market RF
node scripts/growth/acquisition.mjs plan --market KZ
node scripts/growth/acquisition.mjs plan --market UZ
node scripts/growth/acquisition.mjs stats
```

Приватное состояние: `/workspace/.cloud/magic-metal/growth/operations` вне Git.
На другом executor задавать `--state-dir` вне публичного checkout; на Windows
обеспечить ACL. Не перезаписывать вручную изменённые черновики повторным `draft`.
Подробные команды: [ACQUISITION_OPERATIONS.md](ACQUISITION_OPERATIONS.md).
CLI сейчас валидирует только `RF/KZ/UZ`: для иной страны вести точную приватную
квитанцию и не подменять страну поддерживаемым кодом. Расширение CLI — отдельная
небольшая правка с профильной проверкой, если оно действительно требуется.

## Одна площадка: от проверки до результата

1. Проверить официальный бесплатный базовый тариф, ограничения категории/страны и
   существующую карточку по телефону/домену/ИНН. Сохранить источник и дату проверки.
2. Выбрать действие: управление своей карточкой, исправление фактических данных
   либо новая регистрация после проверки дублей. Не присваивать одноимённую фирму.
3. Открыть форму в разрешённом браузере. Проверить окно, URL и живые поля, затем
   заполнить; перечитать адреса, телефон, рубрику и отсутствие платных опций.
4. Отправить один раз. Сохранить показанный результат/номер заявки/безопасный URL.
   Не считать клик успешной отправкой. При неизвестном исходе проверить его перед
   повтором; pending RDC-call продолжать через его результат, а не новой мутацией.
5. При реальном запросе SMS/email/CAPTCHA/входа владельца зафиксировать точный шаг
   и перейти к следующей доступной площадке. Если обязательного достоверного поля
   нет, сначала искать подтверждённый источник; затем спросить только это поле.
6. После модерации открыть публичную карточку и сверить название, адрес нужного
   назначения, контакты и ссылку. Принятая заявка ещё не означает публикацию.

Для текущих карт: 2ГИС `70000001109666787` имеет совпадающий известный телефон;
получить управление и разделить юридический адрес/место приёма. Яндекс
`27021167791` — только кандидат без подтверждённого телефона/сайта: не менять его
телефон ради кода без доказательства принадлежности. В актуальной сессии сначала
проверять состояние кабинета, а не воспроизводить старые ошибки CAPTCHA/входа.

## Статусы и доказательства

| Факт | Запись |
|---|---|
| Черновик подготовлен | `planned`; это не регистрация |
| Нужны код, вход, проверка данных/принадлежности | `needs_verification` + конкретный блокер |
| Площадка подтвердила приём заявки | Квитанция отправки; `submitted` только с соответствующим доказательством |
| Карточка реально доступна и сверена | Квитанция публичной проверки; `published_verified` только с соответствующим доказательством |
| Исход отправки неизвестен | Приватная отметка `outcome_unknown`; сначала выяснить исход |

Последняя строка — отметка в приватной квитанции, не поддерживаемое значение CLI.
Квитанция содержит `platform`, `market`, `observedAt` с часовым поясом
Asia/Yekaterinburg, `action`, `observedStatus`, безопасный `evidenceUrl`, `blocker`,
`nextAction` и `evidenceType`. Хранить вне Git с правами0600/ограниченными ACL.
Секретные ссылки и скриншоты кабинетов хранить отдельно, не вкладывать в публичный PR.

Тип доказательства по умолчанию — `owner_confirmed`. Для результата, реально
наблюдённого агентом, использовать явный тип:

```bash
node scripts/growth/acquisition.mjs record --platform prom-uz --market UZ --status submitted --evidence https://www.prom.uz/company/REAL-PAGE --evidence-type agent_observed --confirmed yes
```

Заменить `REAL-PAGE` фактической безопасной ссылкой на принятую заявку или карточку.
Для `published_verified` сначала отдельно сверить публичную карточку. Не подменять
обычную форму добавления компании ссылкой на доказательство успешной отправки.
В обоих режимах нужны `--confirmed yes`, допустимый HTTPS-домен без query/секретов
и сохранённая квитанция; CLI не делает сетевую проверку. Неизвестный тип отклоняется.
Общее разрешение работать не подтверждает факт публикации. Повторного разрешения
отправить уже согласованную бесплатную форму не требуется.

## Минимальный итог этапа

Число исследованных площадок/черновиков отдельно от отправок и публикаций.
Для каждой реальной отправки — квитанция, для публикации — сверенный публичный
URL, для ожидания — конкретный следующий шаг. Сохранить итог в проектной памяти
и Obsidian и прочитать запись обратно. Продажи оценивать по обращениям →
квалификации → КП → исходу, а не по числу регистраций.

Для этого процесса уже есть RDC и локальный реестр: новый MCP-сервер не нужен,
пока не обнаружен конкретный повторяющийся пробел, который они не закрывают.
При наличии `scripts/growth/directory-browser.mjs` сверить его реализацию и
актуальный результат живого подключения: контроллер служит наблюдению DOM и
выполнению заданий для проверенной конкретной формы. Отдельный CDP-профиль не
наследует вход владельца; переносить cookies/сессии ради этого не следует.
До фактической проверки не объявлять этот контроллер готовым. Новую площадку
проходить через инспекцию её формы, а не через неизменённый шаблон чужого сайта.
Новые секреты хранить вне Git/vault; на Windows использовать DPAPI/PSCredential
и ограниченные ACL, не выводить пароль/OTP в чат, логи или тело PR.
