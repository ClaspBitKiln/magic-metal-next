Рекомендация для начала: выборочно пройти frontend-разделы Easy-Vibe, затем занятия 3 и 5 инженерного курса. Начальные упражнения не требуют переносить наш сайт на другой конструктор или менять стек.

Курс DeepLearning.AI «Vibe Coding 101 with Replit» обнаружен, но официальная страница в этой среде вернула HTTP 403. Его содержание и условия доступа здесь не подтверждены; в основной выбор он не включён.

## Рабочий цикл для нашего сайта

1. **Один пользовательский сценарий.** Например: открыть категорию → выбрать размер → проверить марку/ГОСТ → добавить в КП. Зафиксировать конкретную проблему и ожидаемое поведение.
2. **Контекст для ИИ.** Найти существующий компонент, данные и стиль; приложить скриншот с шириной экрана и масштабом браузера. Прочитать подходящую документацию установленного Next.js из `node_modules/next/dist/docs/`.
3. **Небольшая правка.** Сохранить утверждённую композицию и использовать текущую дизайн-систему. Предпочитать HTML/CSS, если они решают задачу; не добавлять анимацию, библиотеку или клиентский код без пользы для покупателя.
4. **Проверить критерии.** Проверять изменённый маршрут и состояния по уровням AGENTS.md. Для hero проверять 390 px и 1536 px при DPR 1.25: это воспроизводит мобильный экран и дробный масштаб из обращения пользователя.
5. **Подтвердить публикацию.** Перед публикацией — полный линтер и production-сборка один раз на конечную пачку. После неё — статус Vercel и проверка изменённого поведения на `magicmet.ru`. Не отправлять реальные заявки при smoke-проверке.

## Обязательные критерии

- Главный визуальный контент доступен из начального HTML, независимо от загрузки необязательного JavaScript.
- Изображение hero остаётся утверждённым. Описание не заходит в активную область фотографии; в изображении нет белых швов между частями.
- Для статической главной сохраняется проектный бюджет: HTML менее 15 000 байт gzip и небольшие отдельные hero-ресурсы. Это ограничение текущей доставки сайта, а не универсальный стандарт для любой страницы.
- Область нажатия ссылок каталога — минимум 44 px; категории доступны без раскрытия других разделов.
- Поиск не подменяет диаметр, стенку или марку. Нормализация записи не должна создавать ложное наличие.
- Тест должен отличать правильное поведение от прежней ошибки. Проверять неверную толщину, другую марку, отсутствие JavaScript и быстрый переход к товару; не заменять эти проверки проверкой существования элемента.

## Шаблон задания для ИИ

> Сценарий: [действие покупателя]. Проблема: [наблюдаемая ошибка].
> Ожидаемый результат: [измеримое поведение].
> Существующие файлы и компоненты: [пути].
> Ограничения: сохранить утверждённый бренд, данные и скорость; не расширять задачу.
> Проверка: [конкретный запрос, экран или переход], включая отрицательный случай.
> Сначала найди причину, затем сделай одну небольшую правку и проверь результат.

## Применено в текущей работе

- Hero перенесён из JavaScript в HTML; JavaScript уменьшился с 2056 до 1494 байт. HTML после изменения — 12 571 байт gzip. Изображение проверено без JavaScript на пяти ширинах, включая дробный масштаб; текст ограничен левой колонкой, швы устранены.
- Каталог восстановлен из существующих данных: 10 категорий, 45 видов, 90 ссылок; все категории закрыты по умолчанию, область нажатия ссылок не меньше 44 px.
- Запись размера нормализуется, а размер сопоставляется точно; реальные варианты запросов проверены на телефоне и компьютере. Добавлены проверки, исключающие неверную стенку и марку.

Эти наблюдения относятся к выполненным проверкам текущего сайта; показатели LCP/INP/CLS у пользователей отдельно не измерялись.

## Чтение размерных таблиц: 14.10.2026

Сравнены официальные материалы и исходники трёх систем оформления:

| Пример | Полезный приём для каталога |
| --- | --- |
| GOV.UK Design System, Table | Числовые колонки вправо, табличные цифры, выравнивание содержимого по верхнему краю, семантические заголовки и подпись. |
| USWDS, Table | Светлое чередование строк, закреплённая шапка, контейнер с прокруткой для широких таблиц. |
| Bootstrap 5.3.8, Tables | Компактные строки, заметная строка при наведении, сохранение таблицы при горизонтальной прокрутке. |

Прямые запросы к страницам документации завершились `Request was cancelled`,
включая повтор вне песочницы. Поэтому сравнение основано на доступных
официальных файлах GitHub, а не на осмотре недоступных страниц в браузере:

- `alphagov/govuk-design-system`, `src/components/table/index.md`;
- `alphagov/govuk-frontend`, `packages/govuk-frontend/src/govuk/components/table/_mixin.scss`;
- `uswds/uswds`, `packages/usa-table/src/styles/_usa-table.scss`;
- `twbs/bootstrap`, тег `v5.3.8`, `scss/_tables.scss`.

Для наших данных выбрана комбинация: компактная семантическая таблица,
светлые чередующиеся строки, закреплённые шапка и первый столбец. Числовые
колонки выровнены вправо только если все их значения — отдельные числа или
прочерки. Перечни толщин и текст остаются слева. На телефоне показана короткая
подсказка о прокрутке. Результат оценивается по нашим отрисованным таблицам.
Библиотеки оформления и клиентский JavaScript не добавляются.

При визуальной проверке заголовки «Ширина» и «Крепёж» больше не разрываются
внутри слов на узком экране. На 320, 390 и 1536 px проверены размерные страницы
листа, рулона, балки и фланцев; широкая таблица дополнительно проверена
в искусственно суженном до 120 px контейнере. В нём реальный scrollLeft=120 px,
первый столбец остаётся у левой границы. Это отдельный тест ограничения ширины,
а не макет сайта на таком экране. В длинной таблице проверены закрепление
шапки при вертикальной прокрутке и прокрутка с клавиатуры без JavaScript.

## Российские отраслевые примеры: 14.10.2026

После открытия доступа проверены браузером страницы Metal100 «Трубный прокат»
и «Трубы бесшовные х/к» на 1536 и 390 px. Полезный приём: явный выбор размера,
короткая запись D×s и группировка по виду продукции; таблицы имеют подписи
единиц. Наблюдаемая фиксированная ширина части мобильных блоков не перенесена.
Публичная карточка Metal100 также получена через Firecrawl REST API с исходным
HTTP 200. У 23met сначала получены публичные HTML и CSS, затем браузер и
Firecrawl получили ограничение запросов (исходный HTTP 429). MC ответил 503,
ЕВРАЗ — 403; их недоступное оформление не объявляется изученным.

Применено в существующем компоненте: короткий выбор таблиц/типов перед первым
рядом, отдельная метка ГОСТ, первая расшифровка перед таблицей, целые десятичные
значения в списках и немного больше межстрочного пространства внутри списков.
Номинальные данные и все примечания сохранены, новый JavaScript не добавлен.
Каждый размер не превращается в отдельный DOM-элемент, чтобы тысячи сочетаний
не увеличивали объём страницы. Результаты и прежние подключения записаны
в `OBSIDIAN_PENDING_RF_CATALOG_AND_CONNECTIONS_2026-10-14.md`.
