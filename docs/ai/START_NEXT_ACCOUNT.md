## 3. Remote Desktop Commander: точная текущая схема

Это подключение ИИ к разрешённым файлам и процессам Windows. Оно не является Windows RDP/службой mstsc и не требует публикации порта 3389.

Текущая цепочка:
ChatGPT/Codex → подключение Remote Desktop Commander → mcp.desktopcommander.app → клиент remote на Windows → файлы/PowerShell/Obsidian.

На компьютере используется Node.js:
- C:\Program Files\nodejs\node.exe
- C:\Program Files\nodejs\npx.cmd

Клиент: пакет @wonderwhy-er/desktop-commander, режим remote. Устройство 8 ноября показывало версию 0.3.1.

Файлы автоматизации:
- %LOCALAPPDATA%\MagicMetalObsidianSync\Ensure-Remote.ps1
- %LOCALAPPDATA%\MagicMetalObsidianSync\Ensure-Remote-Hidden.vbs

Текущий Ensure-Remote.ps1 сначала ищет node.exe с desktop-commander и remote в командной строке. Если найден — завершает работу без запуска нового экземпляра. Иначе запускает:
- существующий dist/index.js из npm-cache/_npx через node.exe; либо
- npx.cmd --yes @wonderwhy-er/desktop-commander@latest remote, если сохранённой точки входа нет.

Путь конкретного _npx-каталога является локальным кэшем, а не переносимой настройкой. Не копировать старый хеш пути на другой компьютер и не удалять _npx во время работающего доступа.

Задание Windows:
- Имя: MagicMetal Remote Connection.
- Период: каждые 5 минут.
- Действие: wscript.exe запускает Ensure-Remote-Hidden.vbs, тот запускает Ensure-Remote.ps1.
- StartWhenAvailable включён; запрета работы от аккумулятора нет.
- Для параллельных запусков задания установлен IgnoreNew.
- Есть ярлык автозагрузки MagicMetal Desktop Commander Remote.lnk.

Данные привязки и журналы:
- %USERPROFILE%\.desktop-commander-device\device.json — защищённые данные устройства; содержимое не публиковать.
- Там же remote-mon.log ... remote-sun.log — журналы по дням; перед передачей очищать от секретов.

Проверка существующего компьютера:
1. Компьютер включён, Windows работает, интернет доступен.
2. Открыть https://mcp.desktopcommander.app/ и войти в используемую учётную запись сервиса.
3. Если инструменты Remote Desktop Commander уже доступны, сначала проверить list_devices. Отсутствие приложения в поиске каталога не означает, что работающий инструмент нужно переподключать. Только при отсутствии доступа подключить именно Remote Desktop Commander официальным способом; не заменять его случайным похожим приложением.
4. Вызвать список устройств. Найти DESKTOP-BNPIVK2 со статусом Online.
5. Выполнить безвредную проверку: прочитать известную заметку Obsidian и получить свободное место диска.
6. Для проверки записи создать отдельную тестовую заметку в согласованной области vault и прочитать её обратно; существующие заметки не перезаписывать.
7. Если инструмент вернул call_id/status running — опрашивать результат именно этого вызова, а не повторять запись.

Если устройство Offline:
- проверить Node.js, сеть, существующие процессы и задание MagicMetal Remote Connection;
- после проверки отсутствия активного клиента запустить существующий Ensure-Remote.ps1;
- для первой установки/перепривязки выполнить официальный клиент remote в видимом терминале и пройти показанную им браузерную авторизацию;
- не завершать все node.exe: среди них могут быть сайт, MCP и другие рабочие процессы;
- не отзывать старую привязку и не удалять device.json без понимания, какой доступ будет потерян.

Команды для диагностики Windows:
Get-ScheduledTask -TaskName 'MagicMetal Remote Connection','MagicMetal Catalog Sync'
Get-ScheduledTaskInfo -TaskName 'MagicMetal Remote Connection'
node --version
npm --version

Первая установка на новом компьютере:
1. Установить поддерживаемый Node.js LTS с https://nodejs.org/ ; проверить node/npm/npx в новой PowerShell.
2. Запустить: npx --yes @wonderwhy-er/desktop-commander@latest remote
3. Пройти авторизацию, которую покажет официальный клиент. Подключить новое устройство к разрешённому аккаунту сервиса/ИИ.
4. Проверить Online и тестовое чтение до настройки автозапуска.
5. Только затем адаптировать существующие Ensure-Remote-скрипты и задания под нового пользователя/пути. Не создавать копии заданий с одинаковой функцией.
6. Повторить проверку после выхода/входа в Windows и после перезагрузки.

Важно: старый скрипт scripts/start_remote_desktop_commander.cmd в Git использует диагностический скрипт с версией 0.2.51. Это исторический запасной вариант, а не точное описание текущего клиента 0.3.1. Не запускать его поверх работающего доступа.
