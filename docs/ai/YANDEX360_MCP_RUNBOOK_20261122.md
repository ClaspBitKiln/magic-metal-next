## Подключения и авторизация

| Сервис | Endpoint | Транспорт | Заголовок |
|---|---|---|---|
| Mail | `https://mcp.360.yandex.net/v1/mail/mcp` | Streamable HTTP | `Authorization: OAuth TOKEN` |
| Disk | `https://mcp.360.yandex.net/v1/disk/mcp` | Streamable HTTP | `Authorization: OAuth TOKEN` |

**Префикс — OAuth, не Bearer.** TOKEN обозначает секрет; не подставлять буквальную тестовую строку. Для Почты и Диска нужны раздельные токены.

Документированные публичные OAuth client ID — это не секреты:

- Mail: `355734217047470d8064b5dbbf579fee`.
- Disk: `da1cbaa895264f08a7f883ba39427032`.

Штатная авторизация: `https://oauth.yandex.ru/authorize?client_id=CLIENT_ID&response_type=token`. Проверять именно корпоративный m1@magicmet.ru и запрашиваемые доступы. Доступ зависит от действующей подписки Яндекс 360; не подключать платные услуги ради проверки. Не публиковать возвращённый URL с токеном, OTP или значение секрета.

## Рабочие файлы и DPAPI на Windows

Каталог: `%LOCALAPPDATA%\MagicMetalYandex360` под Windows-пользователем **asus**. Развёрнуты четыре файла: `cli.mjs`, `client.mjs`, `save-secure-token.ps1`, `run-secure.ps1`.

Токены хранятся отдельно: `mail.token.dpapi` и `disk.token.dpapi`. DPAPI CurrentUser привязывает секрет к пользователю и машине Windows. ACL оставляет доступ только текущему SID. Runner временно передаёт токен в `YANDEX360_MAIL_TOKEN` или `YANDEX360_DISK_TOKEN` и очищает/восстанавливает окружение в `finally`.

Первый вариант повторного сохранения обнаружил `ACLPrivilegeNotHeld`. Исправление **8912cd6** обновляет только DACL, не владельца/SACL; после него повторное сохранение Disk DPAPI прошло. Не брать старый helper из кэша.

**Новый аккаунт ChatGPT через тот же RDC и Windows asus использует существующие DPAPI-токены.** Одна смена аккаунта ИИ не требует копировать секрет или заново выдавать OAuth. При смене ОС или Windows-пользователя DPAPI не переносим: получить новые токены официальным OAuth. Облачная среда и Windows — разные машины; runtime запускать через RDC на Windows.

## Запуск без токена в аргументах

Нужен Node.js 22+. Исходники находятся в `scripts/yandex360`, на Windows работают развёрнутые копии. Внешних зависимостей нет. Локальные тесты: **8/8 PASS**; они не подменяют отдельные живые проверки выше.

Пример получения актуального списка инструментов:

```powershell
$rt = Join-Path $env:LOCALAPPDATA 'MagicMetalYandex360'
$resultFile = Join-Path $rt ('mail-tools-' + [Guid]::NewGuid().ToString('N') + '.json')
& (Join-Path $rt 'run-secure.ps1') -Service mail -Command tools -OutputFile $resultFile
```

Для Диска заменить сервис на `disk`. Результатный файл создаётся с `wx`, без перезаписи: каждому вызову нужно уникальное имя/timestamp. Для писем и документов использовать приватный файл и читать только нужные поля, не печатать полный ответ.

Для вызова инструмента создать приватный JSON `{"name":"mail.list_folders","arguments":{}}`, затем запустить `run-secure.ps1 -Service mail -Command call -ArgsFile PRIVATE_REQUEST -OutputFile PRIVATE_RESULT`. Имена и параметры других инструментов брать из живого `tools/list`, не угадывать.

Изменения требуют `-Write` и действующего поручения владельца. Это технический предохранитель, не самостоятельное разрешение на запись. Автоматических повторов нет: после таймаута записи сначала прочитать состояние. [Подробная инструкция CLI](YANDEX360_AUTOMATION_TOOL.md).

## Возможности и ограничения

Mail: поиск, чтение, списки, черновики, перемещение, метки, Trash. `mail.read_message` возвращает тело, `mail.get_message` — метаданные. **Отправки писем нет.** Создание папок/правил в прочитанном списке не найдено, поэтому этот этап выполнен штатным UI. Обновление черновика — полная замена, а не патч; сначала прочитать актуальный черновик. Trash — изменение, не безопасное чтение.

Disk: поиск, чтение, download, создание папок, upload, move/copy, Trash, публичные ссылки. Публичная ссылка меняет доступ; не публиковать документы ради проверки. Презентация уже доступна по https://disk.yandex.ru/i/MtfuVaVCHtqfrQ — не создавать дубли без необходимости.
