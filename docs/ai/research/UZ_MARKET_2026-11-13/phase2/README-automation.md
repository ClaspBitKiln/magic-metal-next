  Текущий текст задания: «Срок поставки автотранспортом — от5–7дней»;

- Указывать **Россия → Ташкент**. Не обещать местный склад в Узбекистане и не

- Подпись изображения: **иллюстрация, не фото конкретной партии**. Это уточнение

- RU/UZ должны передавать одинаковые условия. Марку, размер и единицу не менять

  без массы/количества; цена «от» и неизвестный НДС требуют отдельной проверки.

## Цена: две разные задачи расчёта

Все переменные ниже приведены к одной валюте и единице продажи.

```text
P = закупка с НДС22%
K = все издержки продавца: транспорт, оформление, прочие расходы и выбранный резерв
минимальная цена владельца = P + K
экономическая закупка при возмещении НДС = P / 1,22
входной НДС = P - P / 1,22
экономическая себестоимость = P / 1,22 + K
```

Возмещение не происходит мгновенно: денежная потребность включает всю закупку
с НДС и расходы. Возмещение22% не является22% маржой. Если `S` — сопоставимая
выручка без подлежащего уплате НДС, условный вклад равен `S − себестоимость`,
маржа от продаж — `вклад / S`, доходность от чистой закупки — `вклад / (P / 1,22)`.
Это разные проценты; они не доказывают фактическую чистую прибыль.

Рабочий сценарий:450000₽ перевозка+30000₽ оформление/СТ-1 на20т =24000₽/т
до остальных расходов. При меньшей массе рейс автоматически не дешевеет.
Неизвестные пошлины, соответствие, импортные и прочие расходы не считать нулём;
проверять, какие расходы несёт продавец, а какие — импортёр, и отражать это в условиях.
НДС Узбекистана не вычитать/добавлять молча: установить, включён ли он в ориентир.

`owner_floor_rub_t` в заданиях обязан покрывать закупку gross и все относящиеся
затраты. Скрипт контролирует цену против этой границы, но не подтверждает полноту
расходов за оператора. Курс144,53UZS/RUB за13.11.2026 зашит в проверке данного
снимка; для нового КП пересчитать курс, расчёт и границу согласованно.
См. [калькулятор и его допущения](README-calculator.md).

## Порядок следующего запуска при новых изменениях

1. Сверить задания, названия/ID, условия и цены. Убедиться, что другая копия
   обслуживания не выполняется и предыдущая отправка не имеет неизвестного исхода.
2. В рабочем каталоге с актуальными файлами выполнить:

   ```bash
   node --check prom-maintain.cjs
   node prom-maintain.cjs
   ```

   Второй запуск без `--apply` — dry-run: выводит пять планируемых обновлений и
   не обращается к CDP. Нужны Node.js и доступный `playwright-core`, который текущая
   реализация импортирует до проверки dry-run; не выдавать отсутствующую зависимость
   за ошибку кабинета.
3. В том же executor, где уже проверен вход в нужную компанию через локальный
   CDP `http://127.0.0.1:9223`, выполнить один раз:

   ```bash
   node prom-maintain.cjs --apply
   ```

   При необходимости изолированной версионной копии заданий в Windows PowerShell:

   ```powershell
   $env:MAGIC_METAL_PROM_JOBS = 'C:\проверенный-каталог\prom-updates-версия.json'
   node .\prom-maintain.cjs --apply
   ```

   Значение — путь к заранее проверенному файлу, а не URL. Без переменной скрипт
   читает `prom-updates.json` рядом с программой. В успешном запуске использовались
   `prom-maintain-ba92447.cjs` и отдельный `prom-updates-0fcca21.json` в
   `%LOCALAPPDATA%\MagicMetalDirectoryAutomation`; неизвестно завершившаяся передача
   другого файла не должна подменять задания этого запуска.

4. Скрипт читает текущие данные, строит тексты, пропускает совпавшее состояние;
   при изменениях сохраняет и заново открывает карточку. Проверяет цену, наличие,
   RU/UZ-доставку и отсутствие запрещённой формулировки про склад поставщика.
5. При `STOP` сохранить квитанцию, проверить, какие ID уже прочитаны обратно,
   и установить состояние последнего ID. Не сбрасывать журнал и не создавать
   товары заново. Повторять обслуживающий запуск после выяснения исхода.

## Исправленное поведение существующей формы

- Поле цены с маской нельзя заменять обычным `fill`: на существующем значении оно
  способно добавить цифры. Сначала `ControlOrMeta+A`, `Backspace`, затем
  `pressSequentially` и `Tab`; программа сверяет точное число **до сохранения**
  и после повторного открытия. При несовпадении до save запись запрещается.
- CKEditor обновляется официальным `setData`, с ожиданием1000мс после каждого языка.
  Содержимое RU/UZ проверяется до save. Замена описания через `insertText` в этой
  форме не подтвердилась и в успешном запуске не использовалась.
- После сообщения успеха программа ждет перехода через predicate
  `u => u.pathname === '/app/products-all'`, затем открывает точный ID заново.
  Сообщение успеха само по себе не заменяет readback.
- `MAGIC_METAL_PROM_JOBS` позволяет указать отдельный версионный файл заданий.
  Пока предыдущий изменяющий вызов pending, не повторять его и не создавать
  конкурирующую запись в тот же файл. Проверить исход прежде зависимых действий.

Действующие доказательства лежат на Windows в
`%LOCALAPPDATA%\MagicMetalDirectoryAutomation\prom-updated-20261113.json` и
`results\card-1402458.jpg` … `results\card-1402462.jpg` рядом с ним. Это приватные
файлы кабинета: не добавлять их в публичный Git. Описанные проверки уже выполнены
в успешном запуске; повторный запуск ради повторения отчета не нужен.
