# Obsidian — структура знаний Magic Metal

Этот документ задаёт порядок для заметок проекта. Он не перемещает и не изменяет файлы `inn-bot`.

## Каноническая папка

`02 Projects/Magic Metal/`

Все новые заметки Magic Metal создаются только здесь. Параллельная корневая папка `Magic Metal/` считается старым расположением; её записи переносятся только вручную после проверки ссылок и резервной копии.

## Рекомендуемая структура

```text
02 Projects/Magic Metal/
├── 00 Project Hub.md
├── 01 State/
│   ├── Current State.md
│   └── Handoffs/
├── 02 Product/
│   ├── Vision and Boundaries.md
│   └── RFQ Workbench.md
├── 03 Architecture/
│   ├── Procurement Engine.md
│   └── Data Contracts.md
├── 04 Sources/

│   ├── Metalinfo.md
│   └── Logistics.md
├── 05 Research/
├── 06 Decisions/
├── 07 QA/
├── 08 Plans/
└── 99 Archive/
```

## Точка входа

`00 Project Hub.md` должен содержать:

- цель проекта;
- текущий Git repository/branch/commit;
- production URL и статус без секретов;
- последнюю проверенную дату;
- текущий P0;
- ссылки на Current State, активный план, решения и QA;
- явный список «не делать».

## Типы заметок

- **State** — только проверенное текущее состояние.
- **Plan** — будущие действия и критерии готовности.
- **Decision** — принятое решение, причина и последствия.
- **Research** — источники и гипотезы; не считается подтверждённым состоянием.
- **QA** — команды, среда и фактический результат.
- **Handoff** — Context, Branch, Changed files, Tests, Blockers, Next action, Do not do.
- **Archive** — устаревшие записи, сохранённые для истории.

## Правила порядка

1. Не смешивать план и отчёт о выполнении.
2. У каждого факта указывать evidence или Git commit.
3. Не дублировать одну и ту же state-запись в нескольких папках.
4. Старые материалы не удалять: переносить в `99 Archive` с причиной.
5. Не хранить API-ключи, токены, пароли и файлы учётных данных.
6. Даты источника и даты наблюдения хранить раздельно.
7. После изменения кода обновлять Current State только после тестов.
8. Локальная ветка, GitHub и production считаются разными состояниями до проверки.
