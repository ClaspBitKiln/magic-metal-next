# Technical Catalog UI — утверждённое направление карточек magicmet.ru

Дата фиксации: 03.11.2026. Основа — согласованная владельцем концепция **GitBook (навигация) + Technical Datasheet (параметры) + Linear (компактность)**. Это стандарт представления существующих данных, **не разрешение изменять нормативы, марки, размерные ряды или коммерческий ассортимент**.

**Продолжение 03.11:** исторические ограничения публикации пилота в конце документа относятся к первоначальной проверке #130. Последующие проверенные группы и текущий статус публикаций ведутся в [Issue #115](https://github.com/ClaspBitKiln/magic-metal-next/issues/115).

Следующая ограниченная группа — существующие `krug-goryachekatanyj` и `armatura`. Сводка выводит исходные марки/классы, строки `range` и стандарты без изменения каталога. Для круга переход ведёт к имеющемуся `#sizes`; у арматуры таблицы нет, поэтому используется «Указать размер в заявке». Полный перечень марок круга и оговорки о применимости/документах партии сохраняются. Профильный CI проверяет обе карточки на 320/390/1536 в Chromium и Firefox, no-JS и нативный Chromium zoom 200%.

## Цель

Покупатель за первый экран понимает:
1. Что за продукция и какое исполнение.
2. Какие марки/классы перечислены в каталоге (с учётом применимости).
3. Где выбрать типоразмер и найти ГОСТ/ТУ.
4. Как сразу отправить заявку, включая готовую Excel/PDF спецификацию.

**Марка стали/сплава — первостепенный параметр**, а не скрытая внизу страница. Главная/табличный каталог сохраняет марки в последней колонке, если применяется эта утверждённая структура; в подробной карточке марки выносятся в техническую сводку возле размера и стандарта.

## Правила оформления

- Подробная карточка: компактный заголовок, хлебные крошки, техническая сводка в виде таблицы определений, CTA «В заявку», ссылка к размерному ряду.
- Пользоваться существующим CSS, фирменными синими цветами, шрифтами, семантическими `h1/h2/dl/dt/dd`, `a` и реальными текстами.
- Полные размерные таблицы, подробные стандарты, применение и другие поля не удалять. Справочная таблица не является утверждением складского наличия.
- Не дублировать интерактивный выбор размеров. Готовую спецификацию можно отправить без выбора.
- Сначала одна карточка-пилот; на остальные категории переносить **по проверенным группам**, а не глобальным CSS.
- Никаких дополнительных библиотек, web-fonts, излишней анимации или произвольных декоративных блоков.
- Сохранять нетронутыми `#about`, логотип, защищённые клиентские логотипы и desktop hero главной.
- Вопросы совместимости «марка × форма × ГОСТ» и наличие решаются **техническим review**, не внешним видом.

## Критерии приёмки

- Марка, форма/исполнение, ГОСТ/ТУ, точный переход к размерам и заявке доступны на первом экране с учётом высоты устройства; без обещаний склада.
- На 320, 390 и 1536 px — реально проверенные computed размеры заголовков, текста, таблиц, CTA, без общего горизонтального overflow; главные действия минимум 44 px.
- На desktop — настоящий browser zoom 200%, не подмена `deviceScaleFactor` либо уменьшением viewport.
- Пройдены профильные тесты, ESLint, требуемый production build; PR preview/CI и фактическая публичная страница проверяются отдельно.
- RFQ не отправляется реально для UI smoke; подтверждение успешной заявки не симулируется.
