# Этап 15 — Continuous Optimization

## Цель
После запуска улучшать сайт и снабжение по фактическим данным, а не по предположениям.

## Минимальный цикл

`заявка → результат → измерение → вывод → небольшое изменение → проверка → фиксация`

## 1. Что измеряем

### Продажи
- количество RFQ;
- RFQ → КП;
- КП → сделка;
- выигранные / проигранные заявки;
- время от заявки до первого ответа;
- время от заявки до КП.

### Закупки
- выбранный маршрут;
- фактическая цена закупки;
- фактический lead time;
- плановая и фактическая логистика;
- успешность / неуспешность поставки;
- причина проигрыша, если известна.

### Сайт
- отправка заявки;
- поиск товара;
- основные CTA;
- скачивание материалов;
- конверсия ключевых посадочных страниц.

## 2. Что можно менять

Только после появления фактических данных:
- ranking weights;
- supplier reliability;
- приоритет источников;
- SEO/CRO страницы;
- тексты и CTA;
- порядок и удобство каталога;
- логистические параметры.

## 3. Правило изменений

Одно существенное изменение за итерацию. Для каждой итерации фиксировать:

`что изменили → почему → какой показатель должен улучшиться → результат`

Не менять одновременно Procurement Engine, каталог и маркетинговый funnel без необходимости.

## 4. Источники знаний

- GitHub — код, конфигурация, история изменений;
- Payload — заявки и операционные данные;
- Obsidian — решения, фактические выводы, lessons learned.

Новые поставщики и источники сначала добавляются в Master Registry. Никаких скрытых источников, ручных исключений или фиктивных данных.

## 5. Что НЕ делаем сейчас

- не строим отдельную BI-систему;
- не внедряем сложный ML;
- не создаём отдельную CRM;
- не делаем сложную A/B-платформу;
- не добавляем автономные изменения без проверки;
- не усложняем Procurement Engine без подтвержденной бизнес-проблемы.

## 6. Release discipline

Каждое изменение:
1. минимальный scope;
2. targeted test;
3. lint/build при необходимости;
4. production QA для релевантных изменений;
5. commit в GitHub;
6. запись результата в проектную память.

## 7. Критерий успеха

Система должна становиться лучше по измеряемым показателям: быстрее обработка RFQ, выше доля корректных КП, выше конверсия в сделки, меньше закупочных ошибок и ручной работы.

**Этап 15 завершает базовый цикл проекта. Дальше работа идёт итерациями по фактическим данным.**
