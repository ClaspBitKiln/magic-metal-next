# ТРИЗ для исследовательского роя «Сайт2»

Статус: проектное решение, **не production**. Координация #115, #117, PR #118.

## Идеальный конечный результат (ИКР)
Система автоматически и параллельно получает проверяемые сведения о марках, размерах и стандартах из разрешённых публичных источников, не зависит от одного провайдера и не публикует непроверенные факты.

## Противоречия и приёмы ТРИЗ

| Противоречие | Приём | Решение |
| --- | --- | --- |
| Быстрый обход многих сайтов требует браузеров, но браузеры ресурсозатратны | №1 дробление; №3 местное качество | HTTP/HTML сначала, Playwright только для страниц с JS; затем Crawlee для очередей |
| Один инструмент удобен, но его сбой останавливает всё | №15 динамичность; №24 посредник | Единый формат evidence JSON и сменные адаптеры HTTP / Playwright / облачный инструмент |
| Максимальная автоматизация ускоряет, но может публиковать ошибки | №23 обратная связь; №11 предварительная компенсация | Двухэтапная проверка: извлечение → независимая проверка норматива и PR |
| Параллельные агенты быстрее, но два аккаунта могут перезаписать изменения | №1 дробление; №10 предварительное действие | Задания по независимым товарным группам и файлам, отдельные ветки и PR, координация через Issues |
| ГОСТ нужен технически, но покупатель его не знает | №17 переход в другое измерение; №35 изменение параметров | Размер и марка на первом экране; ГОСТ необязателен, «Помогите подобрать» по умолчанию |
| Нужно ускорить исследования без роста затрат | №22 «обратить вред в пользу»; №25 самообслуживание | Использовать уже установленный Playwright, локальный HTTP-парсер и кэш доказательств; не ждать PyPI |

## Практическая последовательность

1. **Агент-диспетчер:** разбить задачу на независимые группы (трубы, СДТ, лист, сортовой прокат, цветные, метизы, UX).
2. **Агент-сборщик:** публичный HTTP с соблюдением robots.txt, таймаутами и лимитами; при необходимости Playwright.
3. **Агент-структуратор:** извлечь наименование, размер, марку, ГОСТ/ТУ, точный исходный URL; отмечать неопределённость и дату.
4. **Агент-критик:** сопоставить с нормативным источником и торговыми компаниями; никакой автоматической подстановки марок между формами продукции.
5. **Агент-ревьюер:** отдельный PR, тесты, визуальная проверка и только затем разрешённый merge.

## Техническая архитектура

- **Уже доступно:** Node.js 24, Playwright в рабочем репозитории; Python 3.11 и отдельный fallback HTML-сборщик.
- **Не подтверждено:** Crawl4AI (PyPI TLS/proxy), Crawlee (пока кандидат, не считать установленным).
- **Защита:** не изменять локальный checkout второго аккаунта, не отключать TLS, не обходить ограничения сайтов, не отправлять реальные заявки.
- **Артефакты:** research JSON → reviewer findings → GitHub PR. Каждое утверждение привязано к проверяемой ссылке и не означает наличия на складе.

## Условия перехода к внедрению

- [ ] Пробное получение двух разрешённых публичных страниц через доступный Playwright/HTTP.
- [ ] Повторяемое извлечение корректных полей и URL без ложных нормативных выводов.
- [ ] Лимиты нагрузки, robots/условия использования, обработка ошибок.
- [ ] Профильный CI и ревью PR до любого изменения production.

**Решение:** начинать с уже работающих ресурсов, вводить новые зависимости только после доказательства их пользы.
