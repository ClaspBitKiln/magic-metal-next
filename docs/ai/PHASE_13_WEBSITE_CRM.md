# Phase 13 — Website / CRM

## Принцип
Не создаём отдельную CRM-систему.

Сайт + Payload Admin уже являются минимальным CRM-контуром заявок.

## Единая заявка
Коллекция `requests` хранит:
- имя, компанию, телефон, email;
- что требуется;
- направление продукции;
- предпочтение происхождения;
- файлы спецификации;
- статус заявки;
- источник, landing page, referrer и UTM.

## Статусы
`Новая → В работе → Предложение отправлено → Закрыта`

Этого достаточно для MVP продаж.

## Передача
Заявка сохраняется в Payload. Дополнительно может отправляться:
- email;
- CRM webhook.

Наличие внешней CRM не является обязательным условием работы сайта.

## Клиентский контур
Клиент видит только форму и результат обработки заявки.
Поставщики, закупочные цены, маржа, источники и внутренние данные CRM наружу не передаются.

## Не делаем на этом этапе
- отдельную CRM;
- сложную воронку;
- роли менеджеров;
- автоматические задачи менеджерам;
- телефонию;
- сложную историю коммуникаций;
- дублирование заявок в нескольких системах.

## Результат
Минимальный рабочий контур:

`Сайт → Заявка → Payload → Email / CRM webhook → Менеджер → КП`

Следующий этап — 14: QA / Security / Production.
