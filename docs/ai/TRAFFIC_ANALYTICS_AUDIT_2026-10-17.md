# Посещаемость и воронка — 17 октября 2026

## Что известно достоверно

На проверенной опубликованной главной и странице горячекатаного листа не было
активных Яндекс Метрики, GA4 или Vercel Web Analytics. Локальные публичные ID
пусты; доступа к историческим отчётам хостинга или кабинета аналитики нет.
Пользователь сообщил, что раньше статистику не смотрел. Поэтому число
посетителей неизвестно — ноль посещений из этого не следует. Не исключается,
что в кабинете хостинга или старом счётчике есть история: без доступа она
не проверена. HTTP-запросы хостинга, письма и заявки не равны посетителям.

Два присланных ранее примера обращений содержат рекламный SEO-текст и случайные
строки; это признаки спама. Этого недостаточно для вычисления доли спама,
конверсии сайта или размера аудитории. Старый HTTP-успех honeypot тоже нельзя
считать реальной заявкой.

Ранее аналитику отменяли; 17 октября пользователь прямо запросил подключение
аналитики для повышения эффективности воронки. Выбран один счётчик Яндекс
Метрики, без дублирования GA4 и установки MCP. Для чтения используется прямой
официальный API: MCP не даёт доступа без авторизации и не восстанавливает
историю, которая не собиралась. На GitHub рассмотрены официальный
`googleanalytics/google-analytics-mcp` и read-only `ShalomGH/yandex-metrika-mcp`;
чужой код не устанавливался и не исполнялся.

## Подготовленное подключение

- Одна отложенная загрузка `analytics.js`, затем SDK Метрики после load/idle.
- Главная остаётся статической, hero и каталог не зависят от счётчика.
- Без валидного ID счётчик и его клиентский компонент не подключаются.
- События: переходы в продукцию/справочник/заявку, фильтр и выбор размеров,
  телефон/email, начало формы, второй шаг React-формы, вложение, успешная
  приёмка, ошибка отправки.
- `request_sent` только при сохранении заявки или подтверждённой доставке;
  один `{ok:true}` от honeypot не даёт цели.
- В события не передаются телефон/email, текст заявки, выбранные размеры,
  имена файлов. Из URL счётчика удаляются product/material/standard и другие
  параметры кроме разрешённых UTM и yclid. Вебвизор и карты кликов выключены.
- Подготовлены идемпотентный setup и read-only отчёт через API. API-токены
  не попадают в браузер, публичные переменные, Git или вывод программы.

## Анализ после появления данных

Сначала проверяем полноту измерения и тестовые/роботные визиты, затем:

1. Посетители, визиты и просмотры; равные завершённые периоды с учётом даты
   установки, часового пояса, семплирования и задержки данных.
2. Источники/кампании и посадочные: трафик, интерес к продукции и заявки,
   отдельно мобильные/настольные устройства. Малые выборки не ранжируем
   уверенно по конверсии.
3. Каталог → работа с размером → переход к заявке → начало → вложение →
   сохранённая/доставленная заявка. Это события пути, не доказательство
   линейного прохождения каждым посетителем.
4. Отдельно коммерчески подходящие заявки, КП и сделки: нужны статусы
   менеджера/CRM. Событие формы не доказывает продажу или качество лида.
5. Одно изменение за раз в проблемном месте, затем сравнение сопоставимых
   источников/устройств. Рост недавно установленного счётчика относительно
   отсутствующей истории нельзя выдавать за рост бизнеса.

## Состояние активации

Код подготовлен и проверен с подставным SDK, без отправки данных в чужой
счётчик. Реальные API-запросы к кабинету не выполнялись: отсутствует
авторизация Яндекс-аккаунта и номер счётчика. Для активации необходимы
публичный ID и защищённый API-доступ; программу создания счётчика/целей
можно выполнить после такой авторизации. Установка пакета или публикация
подготовленного кода сама по себе не означает, что сбор данных уже начался.

## Проверки подготовленного кода

12 профильных тестов аналитики/согласия и 7 офлайн тестов API прошли.
Полный ESLint и production-сборка прошли. Браузер проверил три подставных
отправки: ошибку, сохранённую заявку и honeypot. Реальных писем и данных
в чужой счётчик не отправляли; SDK был подставным. Поля формы в событиях
отсутствуют, файл сохраняется после ошибки.

Без активного счётчика главная: HTML gzip 12082 байта (было 12077), один
скрипт; home.js 1331 байт gzip (было 1017). Подготовленный analytics.js
загружается только после указания ID.

Одна контролируемая пара Lighthouse 13.5.0 на локальных статических
копиях, холодный кеш, стандартная мобильная симуляция: до/после LCP
1378/1439 мс, CLS 0/0, TBT 0/9 мс, Performance 100/100. Это небольшой
лабораторный разброс одной пары, не полевые показатели и не доказательство
нулевого влияния. SDK Метрики в этом замере не активен; после реальной
активации необходимо отдельно замерить его влияние.
