# MAGIC METAL — MASTER PLAN

> Единый рабочий план проекта. Выполнять строго по этапам сверху вниз. После завершения каждого этапа: проверить результат, зафиксировать изменения в GitHub, обновить статус и только затем переходить дальше.

## 0. НЕИЗМЕНЯЕМЫЕ ПРИНЦИПЫ

1. Публичный каталог единый: клиент не выбирает поставщика и не видит внутренние источники.
2. Публикуем только позиции, для которых существует реальный и проверяемый маршрут закупки.
3. Внутренние слои поставщиков, цены закупки, маржа, источники и ранжирование скрыты от клиента.
4. Базовый справочник — прайс/номенклатура Металлсервис как отдельный внутренний слой ходовых позиций.
5. Все поставщики/заводы — отдельные внутренние слои данных, без переключателя для клиента.
6. Наличие клиента: `На складе` / `Наличие уточняется` / `Под заказ`.
7. SDT — обычная категория единого каталога.
8. Размеры и практическая номенклатура сопоставляются с ГОСТ и рыночными размерами, но справочные позиции без закупочного маршрута не становятся продаваемыми.
9. Выбор поставщика делается по полной себестоимости поставки (landed cost), а не только по цене материала.
10. Реальные источники важнее красивой витрины: никаких фиктивных цен, наличия, API или поставщиков.
11. Все секреты только в локальном окружении/секрет-хранилище; в GitHub их не помещать.
12. Obsidian — постоянная база проектных знаний; GitHub — технический source of truth и резерв.

# ФАЗА 15 — РЕЛИЗ И НЕПРЕРЫВНОЕ УЛУЧШЕНИЕ

### Цель
После запуска улучшать сайт и снабжение по фактическим данным, а не по предположениям.

### Минимальный цикл
`заявка → результат → измерение → вывод → небольшое изменение → проверка → фиксация`

### Измеряем
- количество RFQ;
- RFQ → КП;
- КП → сделка;
- выигранные / проигранные заявки;
- время до первого ответа;
- время до КП;
- выбранный закупочный маршрут;
- плановая/фактическая закупочная и логистическая экономика;
- фактический lead time;
- успешность поставки;
- ключевые CTA, поиск и конверсию сайта.

### Разрешенные улучшения
- ranking weights;
- supplier reliability;
- приоритет источников;
- SEO/CRO страницы;
- тексты и CTA;
- каталог;
- логистические параметры.

### Правило
Одно существенное изменение за итерацию. Фиксировать `что изменили → почему → ожидаемый показатель → фактический результат`.

Новые поставщики и источники сначала добавляются в Master Registry. Никаких скрытых источников и фиктивных данных.

### Не усложняем без доказанной необходимости
Не строим отдельный BI, ML, CRM или сложную A/B-платформу. Не разрешаем автономные изменения без проверки.

### Release discipline
`targeted test → lint/build при необходимости → production QA для релевантных изменений → GitHub commit → запись результата в проектную память`.
