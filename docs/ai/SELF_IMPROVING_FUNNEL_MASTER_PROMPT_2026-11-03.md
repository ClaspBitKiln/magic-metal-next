# MASTER PROMPT — самосовершенствующаяся воронка без усложнения

Цель: последовательно улучшать **систему продаж magicmet.ru** от целевого поиска до повторного заказа. Не менять утверждённый каталог без доказанного основания. Принципы: ТРИЗ, теория ограничений, минимальная сложность, реальные данные прежде гипотез.

## Роли независимого роя
1. **Измеритель:** проверяет валидность Яндекс Метрики, роботов, одинаковую когорту визитов, источники, регионы и статистическую достаточность.
2. **Диагност:** находит текущее ограничение конверсии; отделяет наблюдение от причины.
3. **UX-инженер:** предлагает максимум 1–2 самых простых исправления, не добавляя обязательных полей и новых сервисов.
4. **QA-критик:** проверяет контрпримеры, мобильность, обе формы, запись/доставку заявок и риск потери лидов.
5. **Оркестратор:** выбирает одну приоритетную гипотезу, изолированный PR, критерий успеха и отката; **не** публикует изменения автоматически.

## Исполняемый промпт
«Прими обезличенную агрегированную статистику Метрики для одного одинаково определённого сегмента и периода; исключи роботов, QA и очевидных ботов. Проверь последовательность посещений: товар → переход к заявке → начало формы → серверно подтверждённая заявка → обработана менеджером → КП → заказ. Если данных недостаточно, точно назови пробел и остановись. Найди одно главное ограничение, сформулируй проверяемую гипотезу, самый небольшой оригинальный UX/технический патч, ожидаемые последствия, защитные метрики, условия отката. Сначала тесты на моках, потом preview/CI и ручное утверждение PR. Не придумывай цифры, наличие металла, марки и ГОСТы; не отправляй реальные заявки и персональные данные». 

## Что подтверждено изучением GitHub 03.11.2026
- https://github.com/PostHog/posthog — событийная продуктовая аналитика (подход к путям и воронке).
- https://github.com/growthbook/growthbook — контролируемые эксперименты и feature flags (подход к гипотезам/откату).
- https://github.com/langchain-ai/langgraph — stateful orchestration (подход к этапам/состоянию). Для данного масштаба отдельный графовый сервер не нужен.
- https://github.com/openai/openai-agents-python — разделение агентов, передачи задач, guardrails и трассировок. Полноценную платформу не добавляем.
- https://github.com/microsoft/autogen — **архивный проект, поддержка прекращена**; как новую зависимость не использовать.

## Реально исполнено в текущем PR
- `scripts/growth/prioritize-funnel.mjs`: маленький локальный, безопасный, проверяющий входные данные механизм выбора потенциального ограничения по сопоставимым агрегированным визитам. Не «сам обучается», не является настоящим агентом и не исправляет сайт автоматически.
- Вход только агрегат JSON с подтверждённой когортой и исключёнными роботами. Мало данных/несовместимые числа → отказ от рекомендаций, а не выдуманный вывод.
- Никаких новых зависимостей, сервисов, GitHub Actions cron или доступа к CRM.

## Следующее условие запуска
Использовать уже работавшее защищённое подключение Яндекс Метрики (см. `docs/ai/METRIKA_CONNECTED_2026-10-31.md`). **Нельзя** складывать полные отчёты с PII и токены в GitHub. Текущая Windows-среда не наследует OAuth из прежнего облака. Полные реальные данные и метрики сделки пока отсутствуют.

После достоверной диагностики один отдельный PR с изменением сайта, профильным QA и фактическим сравнением конверсии. Нет основания — не меняем.
