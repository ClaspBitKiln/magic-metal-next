## Миграцию можно подготовить без production-доступа

Штатный `payload migrate:create initial` инициализирует Payload с
`disableDBConnect: true` и `disableOnInit: true`. Генератор строит Drizzle-схему
из конфигурации, сравнивает её с последним JSON snapshot либо пустой схемой
и создаёт TypeScript миграцию, JSON snapshot и индекс миграций.

Это уточняет прежнее предположение: **для генерации начальной миграции
действующее подключение к production БД не требуется**. Требуются только
локальные значения обязательных переменных для загрузки config. Их можно
передать одному процессу: URI локального тестового PostgreSQL и случайный
локальный Payload secret. Production значения для этого не нужны.

Команда из существующего проекта:

```bash
npm run payload -- migrate:create initial
```

Команда изменит `src/migrations`; перед запуском нужно сохранить исходное
состояние checkout и исключить случайные изменения generated types.
После отдельного расширения задачи генерация выполнена штатной командой:
exit code 0. Переданы только process-local случайный secret и URI loopback
на порт 1: действующего подключения к БД для генерации не было.
Созданы `src/migrations/20261030_174128_initial.ts`, соответствующий JSON snapshot
и `src/migrations/index.ts`. Конфигурация Payload и зависимости не изменены.

Snapshot содержит 20 таблиц, включая `requests`, `request_files`,
`requests_rels` и `users`. Профильный TypeScript check только файлов миграции
(`--noEmit --skipLibCheck --target es2022 --module esnext --moduleResolution bundler`)
прошёл; JSON snapshot разобран, `git diff --check` прошёл.

Первоначальная проверка ограничивалась генерацией и типами. Затем выполнена

К production БД миграция не применялась.

## Зачем миграция нужна в production

Установленный PostgreSQL adapter выполняет автоматический `pushDevSchema`
только при `NODE_ENV !== 'production'`, `PAYLOAD_MIGRATING !== 'true'`
и `push !== false`. Таким образом, успешный локальный dev push не доказывает
создание схемы в production. Для воспроизводимого production развёртывания
нужны сохранённая миграция и её применение штатной командой `payload migrate`.

До production миграцию следует применить к отдельной пустой локальной БД,
проверить таблицы/связи и повторный запуск без повторного изменения схемы.
Не применять initial migration к неизвестной существующей базе вслепую.
