# Локальный клиент официального MCP Яндекс 360

22.11.2026. Клиент подготовлен для Почты и Диска. Это **не подтверждение подключения корпоративного аккаунта**: OAuth-токенов для живой проверки пока нет. MCP Яндекса находится в предварительной версии; браузер остаётся резервным доступом.

## Запуск без установки зависимостей

Нужен Node.js 22+. Программа: `scripts/yandex360/cli.mjs`, протокол: `client.mjs`. Она использует только официальные адреса, `Authorization: OAuth …`, Streamable HTTP, инициализацию, JSON/SSE и заголовок сессии. Перенаправления запроса запрещены, чтобы не передавать токен другому серверу. Автоматических повторов запросов нет.

1. Получить отдельные OAuth-токены Почты/Диска в корпоративном аккаунте **m1@magicmet.ru** по официальной инструкции. Проверить аккаунт перед выдачей доступа. Для MCP нужна действующая подписка Яндекс 360, в том числе для бизнеса. Токены не передавать в чат и не записывать в Git/Obsidian.
2. Передать токен из защищённого хранилища в окружение процесса: `YANDEX360_MAIL_TOKEN` или `YANDEX360_DISK_TOKEN`. Клиент не читает `.env` автоматически. Не указывать токен аргументом команды или литералом в сохраняемой истории терминала. На Windows права файла не защищаются Unix-режимом `0600`: использовать закрытую личную папку/ACL, при настройке хранилища — DPAPI.
3. Выполнить `node scripts/yandex360/cli.mjs mail tools` либо `disk tools`. Реальный ответ сервера показывает текущие инструменты и их JSON-схемы. Не угадывать параметры по старым примерам.
4. Создать **приватный** JSON-файл запроса, например для списка папок: `{"name":"mail.list_folders","arguments":{}}`. Запуск: `node scripts/yandex360/cli.mjs mail call --file /private/request.json --output /private/result.json`. Выходной файл создаётся без перезаписи; в Unix режим `0600`. Без `--output` ответ печатается в терминал, поэтому для писем и документов использовать приватный файл и читать только нужные поля.
5. Изменяющие инструменты требуют явного `--write`. Перед перемещением письма/изменением черновика сохранить исходное состояние и параметры; после выполнения прочитать обратно результат. При таймауте сначала проверить состояние сервиса, не повторять запись вслепую.

## Windows: DPAPI вместо открытого файла с токеном

Скопировать рядом **все четыре рабочих файла** `cli.mjs`, `client.mjs`, `run-secure.ps1`, `save-secure-token.ps1`, например в `%LOCALAPPDATA%\MagicMetalYandex360\bin`. Не копировать приватные токены в репозиторий. Нужны текущий пользователь Windows, PowerShell 5.1+ и Node.js 22+.

Первичное сохранение: `powershell -NoProfile -File save-secure-token.ps1 -Service mail`. Токен вводится через скрытый `Read-Host -AsSecureString`. Для автоматического переноса из авторизованного OAuth-браузера разрешён `-FromEnvironment MAGICMET_YANDEX360_NEW_TOKEN`: это **имя переменной**, а не сам токен. Вызывающий процесс передаёт токен в окружении дочернего PowerShell, не в аргументах, логах или URL-выводе; после завершения удаляет временную переменную. Повторная запись существующего токена требует `-Force`, только при намеренной замене.

Хранилище: `%LOCALAPPDATA%\MagicMetalYandex360\mail.token.dpapi` и `disk.token.dpapi`. Сохраняется шифротекст DPAPI **CurrentUser**, папка получает ACL только для текущего SID. Скрипт проверяет, что шифротекст читается обратно, не печатая токен. Токены нельзя переносить на другой компьютер/аккаунт простым копированием; там получить доступ заново. Расшифровка защищает хранение, но Node при запросе закономерно получает токен в памяти и окружении процесса.

Команды:

```powershell
.\run-secure.ps1 -Service mail -Command tools
.\run-secure.ps1 -Service mail -Command call -Tool mail.list_folders -ArgsFile C:\private\args.json -OutputFile C:\private\folders-result.json
.\run-secure.ps1 -Service disk -Command tools
```

В примере `args.json` содержит только `{}`. Без `-Tool` файл `-ArgsFile` должен содержать полный запрос с `name`/`arguments`. Для записи добавить `-Write`. Результаты с письмами/документами всегда сохранять в закрытую папку. Вызов Node передаётся массивом аргументов, токен не попадает в строку команды; после запуска временная переменная окружения удаляется либо восстанавливается её предыдущее значение. Временный JSON-запрос очищается, BSTR освобождается с обнулением. Открытая строка в памяти CLR не имеет гарантированного немедленного обнуления, поэтому скрипт должен работать коротким отдельным процессом.

PowerShell-обёртки подготовлены для Windows 5.1, но в текущем Linux-окружении их исполнение **не проверено**. Перед объявлением настройки готовой проверить парсер Windows, запись/чтение DPAPI на фиктивном токене в изолированном тестовом каталоге и затем живой `tools/list` с корпоративным аккаунтом. Нативный Codex MCP-конфиг с OAuth-заголовком здесь не менялся: CLI работает отдельно и не добавляет инструмент автоматически в текущую беседу.

Список инструментов, разрешённых без `--write`, задан явно в `READ_TOOLS`; неизвестный инструмент не выполняется автоматически, даже если сервер назвал его безопасным. Для вызова проверяется, что имя принадлежит выбранному сервису и сервер действительно объявил инструмент. `--write` — технический предохранитель, не замена указаний владельца и правил площадки.

## Применение к работе компании

- Почта: поиск ответов каталогов, чтение письма и вложений по его ID, поиск заявок, подготовка черновика ответа. `mail.get_message` не заменяет `mail.read_message`: тело доступно через второй инструмент. Временные ссылки на вложения также считать приватными.
- Диск: поиск актуальных презентаций, спецификаций и сертификатов; скачивание по временной ссылке; создание папок и сохранение новых файлов с проверкой результата. Не публиковать документы или ссылки без соответствующего поручения.
- Папки и автоматические правила входящей почты настраиваются в веб-интерфейсе: **не придумывать MCP-инструмент создания правила/папки, если его нет в актуальном `tools/list`**. Текущая CLI сама не устанавливает такие правила.
- Официальный MCP Почты поддерживает **черновики, а не отправку писем**. Клиент не является почтовым рассыльщиком. Отправка, если отдельно поручена, остаётся штатным интерфейсом почты.
- Планировщик, фоновый сервис, автозапуск и OAuth-обновление этим инструментом **не установлены**. Пока живое подключение не проверено, не объявлять круглосуточную автоматизацию готовой. Предыдущий запрос владельца: периодические проверки не чаще одного раза в 6 часов; отдельно подтверждать фактическую установку расписания.

## Проверка и восстановление

`node --test scripts/yandex360/client.test.mjs` — локальные проверки на тестовом HTTP-сервере: OAuth/сессия/пагинация, JSON и SSE, запрет записи по умолчанию, отсутствие повторов после ошибки, сверка объявленных инструментов, удаление токена из ошибок и ответов. Тестовые токены вымышленные. Локальные тесты не доказывают доступ к m1.

Токен отзывается через Яндекс ID → Данные → Доступ к данным → внешний ИИ-агент Почты/Диска. После отзыва или ошибки 401 заново получить доступ по официальной инструкции. Не менять пароль владельца ради MCP.
