## Что доказано, а что требует отдельной оценки

**Доказано дублирование источников.** Маршрут `/` читает `public/home-static.html`.
`renderApprovedCatalogGrades` в `src/app/(frontend)/route.ts` заменяет только
ячейки марок для `categorySlug === 'cvetnye-metally'` данными
`productDetailCatalog`. Поэтому сравнение сырого HTML с данными шире,
чем сравнение фактически отдаваемой главной.

Например, сырой HTML перечисляет у баббита `Б83 · Б83С · Б88 · Б16 · БН · БТ`,
а карточка — `Б88, Б83, Б83С, Б16, БН, БС6` с оговоркой о применимости.
Это реальное расхождение исходных перечней (`БТ` / `БС6`), но текущая
подстановка главной использует перечень карточки. Оно не доказывает ошибку
живого HTML или нормативную правильность одной марки относительно другой.

**Доказано различие объёма информации вне цветных металлов.** Подстановка
не охватывает следующие примеры:

- Бесшовные горячедеформированные: в данных дополнительно есть `30ХГСА`,
  `12Х1МФ-Ш` и оговорка «по марке и ТУ», отсутствующие в статической ячейке.
- Лист г/к: статическая ячейка содержит `Ст3 · 09Г2С · 20 · 45 · С345 и другие
  по НД`; данные дополнительно перечисляют `С245`, `С255`, `С355`, `16ГС`,
  `17Г1С`, `10ХСНД`, `65Г` и условие проверки применимости.
- Нержавеющие трубы: в данных дополнительно есть `08Х18Н10Т`, `08Х17Т`,
  `AISI 316L` и условие соответствия стандарту по заказу.
- Поковки по чертежу: статическая ячейка — «по чертежу и нормативному
  документу»; данные содержат примеры марок из презентации с условиями
  изготовления и контроля.

Неполный компактный перечень сам по себе не является ложным утверждением.
Для этих примеров установлено различие представлений, а не нарушение ГОСТ.
Без проверки назначения сокращения и применимости марок нельзя механически
заменять утверждённые тексты главной длинными строками из карточек.

**Часть отличий явно относится к компактному изложению.** Например,
«ГОСТ 34028-2016 — арматурный прокат» и полный вариант «…для железобетонных
конструкций»; «ГОСТ 3826-82 — тканые» и «…тканые с квадратной ячейкой».
Их не следует исправлять как нормативные ошибки только из-за неравенства строк.

  Это не полная сверка всех ячеек с результатом `GET /`.

  отсутствие страницы Vercel Login. Ответ 200 не подтверждает нужный товар,

  ежедневно и после успешного production deployment; выполнение workflow
