# Стабильный первый экран поиска — 28 октября 2026

## Причина и исправление

При прямом переходе `/poisk?q=12Х1МФ` статическая страница сначала показывала
40 общих результатов. После hydration mount-effect восстанавливал q из URL
и оставлял семь результатов. Та же ссылка марки перемещалась с y1412 на y833:
это дало 81,4% desktop CLS. Autofocus не вызывал прокрутки (scrollY=0).

Использован стандартный Next 16 подход: Page ожидает searchParams, передаёт
initialQuery в CatalogSearch; первый SSR уже содержит правильные результаты.
При повторном q используется первое значение, как URLSearchParams.get.
React key={initialQuery} сбрасывает состояние при новом серверном URL запроса;
обычный ввод и фильтры продолжают работать без серверного запроса на каждый символ.
Эффект восстановления q при mount удалён, popstate-подписка сохранена.

Только `/poisk` стал request-rendered вместо статической генерации. База данных
в поиске не используется; главная, категории и карточки не переведены в dynamic.
Это осознанный обмен статического кэша поиска на корректный первый HTML и SSR.

Остальная причина: фильтры сначала имели браузерные Arial/normal и высоту40px,
а после отложенного site.css — наследуемый шрифт, line-height18,6px и высоту44,594px.
В локальном search.css заданы font-family:inherit и line-height:1.55, как в
окончательном оформлении. Размеры шрифтов и финальная композиция не менялись.

## Проверка публикации и сжатия

Workflow дополнен двумя запросами поиска без JavaScript на390/1536px:
серверный HTML должен уже содержать введённую марку и правильный первый результат.
В прежних12 сценариях главной сохраняются mobile без фотографии и жирные синие контакты.

Добавлены реальные Content-Encoding/Cache-Control/Vary/Content-Length заголовки
production главной. Прежний htmlGzip — локальный gzipSync после декодирования,
он не доказывает сжатие CDN. Runtime compression не менялся по предположению.
Публичное состояние подтверждается только отчётом sourceCommit итоговой версии.

Lighthouse server-response-time: до (ближайшая прежняя пачка) mobile2ms /
desktop14ms; после12/13ms. Это localhost audit без cold start/edge; не
прогноз для пользователей. HTML поиска: 96857→80440 декодированных байт,
после18123Б передано по сети. На динамическом маршруте ожидается меньшая
эффективность общего CDN-кэша; результат нужно оценивать с учётом этой границы.

Граница результата: исследован текстовый запрос марки12Х1МФ. Поиск размеров
по нормативным таблицам продолжает асинхронно получать API-результаты; улучшение
этого замера не доказывает нулевой CLS для всех вариантов размерных запросов.
Независимый review не выявил блокирующих регрессий; зависимости не добавлены.
