# Приватные вложения CMS — 31 октября 2026

Ветка `codex/cms-private-storage-20261031` подготовлена отдельно от опубликованных
рельсов/канатов. Production-инфраструктура не создавалась, миграции к ней не
применялись. В этой среде runtime secrets/identities пусты; manifest AWS также
не содержит подключений. Имеющаяся локальная PostgreSQL — среда разработки.

## Реализация

- Официальный `@payloadcms/storage-s3` закреплён на **3.88.0**, как и Payload.
  Версии прежних зависимостей не обновлялись.
- Адаптер применяется только к `request-files`. Медиа сайта не переносились.
- Клиентских загрузок, прямых публичных URL и signed download URL нет.
  Скачать файл можно через Payload с существующим `isAuthenticated`.
- ACL не задаётся: AWS BucketOwnerEnforced может отклонить даже `private` ACL.
  Сам bucket должен быть приватным с BlockPublicAccess/эквивалентной политикой.
- Prefix/alwaysInsertFields не включены; проверено совпадение полей коллекции
  с включённым и отключённым адаптером. Новая миграция схемы не требуется.
- В production локальное сохранение отключено. `beforeOperation` отклоняет
  create/update с файлом, если постоянное хранилище не настроено, в том числе
  при Local API `overrideAccess:true`. Публичная сборка без S3 остаётся доступной.
- Существующий SMTP fallback сохранён. При недоступности CMS письмо может
  доставить заявку, но это не доказательство сохранения в CMS.

## Защищённая конфигурация deployment

Нужны существующие production `DATABASE_URL` и `PAYLOAD_SECRET`, затем отдельный
приватный S3/S3-совместимый bucket и четыре серверных параметра:

| Переменная | Назначение |
|---|---|
| `REQUEST_FILES_S3_BUCKET` | имя приватного bucket |
| `REQUEST_FILES_S3_REGION` | регион провайдера |
| `REQUEST_FILES_S3_ACCESS_KEY_ID` | серверная идентификация только этого хранилища |
| `REQUEST_FILES_S3_SECRET_ACCESS_KEY` | серверный ключ, хранить только в защищённых настройках |
| `REQUEST_FILES_S3_ENDPOINT` | необязательный HTTPS endpoint S3-совместимого провайдера |
| `REQUEST_FILES_S3_FORCE_PATH_STYLE` | необязательное true/false по требованиям провайдера |
| `REQUEST_FILES_S3_SESSION_TOKEN` | необязательный токен временных credentials |

Заполнять связанную конфигурацию целиком. Частичная настройка отклоняется;
ошибка перечисляет только имена недостающих переменных. Значения не включать
в Git, чат или отчёты. Proxy-placeholder не подходит для локального SigV4:
credentials должны быть доступны серверному процессу deployment.
Для локального эмулятора разрешён HTTP только на loopback; production — HTTPS.
Bucket не должен разрешать публичное чтение даже при известном имени объекта.
Серверу нужны права Put/Get/DeleteObject и необходимые bucket-level операции
только в выделенном bucket; CORS для публичных клиентских загрузок не нужен.

Перед initial migration проверить целевую схему и резервную копию. Существующую
неизвестную БД не считать пустой. Данные локальной БД не переносить как production.

```sh

node --import tsx scripts/check-request-file-storage.ts
```

Скрипт использует только локальный compose postgres и отдельную БД с уникальным
именем; production DATABASE_URL не читает. В production-режиме запуск запрещён.
При необходимости путь к модулю эмулятора задаётся `S3_TEST_EMULATOR_MODULE`.

## Не подтверждено

Перед подключением можно выполнить **только чтение** реальных настроек из
авторизованного серверного окружения:

```sh
node --import tsx scripts/check-production-cms.ts
```

Скрипт не загружает локальный `.env`: параметры должны уже быть переданы процессу
через защищённые настройки. Без них завершится с кодом 2 и списком имён,
без значений. Loopback-БД отклоняется как production-проверка. Для PostgreSQL
соединение принудительно read-only, запрос читает только имена таблиц; нет
инициализации Payload, DDL, записей, миграций или SMTP. S3 проверяется через
HeadBucket и GetPublicAccessBlock; файлы не записываются и не удаляются.
Неподдерживаемая провайдером проверка политики возвращает «не подтверждено»,
а не ложный успех. `preflight-passed` не подтверждает права записи и не заменяет
проверку приватного скачивания. Соединения требуют разрешённой сети именно
окружения выполнения; ошибка доступа не означает необходимость нового ключа.

В текущей среде получен `blocked`: отсутствуют все шесть production-параметров.
Три теста раннего отказа, защиты значений и endpoint-проверки прошли; ESLint
скрипта и теста прошёл. Фактических production-запросов при этом не выполнялось.

Реальный bucket, его запрет публичного чтения, production DB/deployment bindings,
миграция и end-to-end чтение вложения живой заявки. Не публиковать эту ветку
как «CMS подключена». Сначала проверить существующие защищённые настройки во
втором аккаунте. Новые реальные заявки и SMTP требуют отдельного основания.
Несколько файлов и заявка сохраняются отдельными операциями: при позднем
сбое возможны осиротевшие объекты; атомарность всей заявки здесь не заявляется.
