# ТРИЗ: подача размеров для закупщика, 17.10.2026

Главный пользователь — закупщик. Его задача: быстро найти позицию из
спецификации и отправить запрос предложения с корректным контекстом.
Подбор технологического исполнения и изучение всего ГОСТ не должны быть
обязательными шагами перед заявкой.

## Противоречие и решение

Идеальный конечный результат: закупщик переносит известный размер либо
прикрепляет файл и получает понятный следующий шаг. Проверенные данные
и нормативные ограничения сохраняются.

Техническое противоречие: увеличение полноты таблицы помогает проверить
размер, но увеличивает объём сканирования и число решений перед заявкой.
Разделение по ситуации использования снимает противоречие:

- «Ввести размер» — основной путь, когда позиция уже известна.
- «Выбрать по шагам» — помощь при неполной спецификации.
- «Матрица» — вспомогательное сравнение соседних размеров.

Применённые принципы ТРИЗ: отделение справки от основного действия
(принцип 2), локальное качество представления под задачу (3),
предварительное действие — образцы ввода и распознавание единиц (10),
динамичность — стенки только выбранного диаметра (15), изменение
размерности — матрица для сравнения, не как стартовый экран закупки (17).
Это анализ противоречий и проверка интерфейсов, не исследование конверсии
на выборке реальных закупщиков.

## Три рабочих варианта

`/catalog-variants.html` — отдельная страница сравнения, noindex/nofollow.
Три равноправных переключателя предназначены для сравнения вариантов;
на рабочей странице не следует заставлять закупщика сначала выбирать
тип интерфейса. Рекомендация — поиск размера и прикрепление файла как
основной путь, подбор и справочная матрица как вспомогательные режимы.

| Вариант | Сценарий | Наблюдение |
| --- | --- | --- |
| Ввод размера | Вставить 108х4 мм → найти → запросить предложение | Один размер из спецификации, короткий результат; стандарт и условия доступны отдельно |
| Пошаговый | Диаметр 108 → одна из его 28 стенок → заявка | Неподходящие стенки не предлагаются; на телефоне список кнопок занимает больше места |
| Матрица | Диаметр → пересечение → заявка | Соседние размеры сравниваются, но на телефоне требуется горизонтальная прокрутка |

Во всех вариантах заметна ссылка «Прикрепить спецификацию», ведущая в
существующую форму с файлами, без корзины. Пустой результат содержит
ссылку на запрос проверки, сохраняющую введённый размер. Строка 108×0,3
не превращается в подходящее сочетание. 108×1,5 получает реальную оговорку
о согласованной документации из примечания 3; она передаётся в заявку.

## Данные и границы

Один и тот же основной ряд ГОСТ 8734-75: 71 диаметр, 39 различных
толщин, 1733 сочетания. Это не декартово произведение. Дополнительный ряд
по примечанию 2 не включён: отсутствие 32×8,5 в этом наборе не объявляется
невозможностью его изготовления. Диаметр — наружный, не DN.
Марка, длина, объём и наличие не выводятся из одной размерной таблицы.

`public/data/catalog-variant-pipes.json` создаётся штатными данными через
`scripts/build-catalog-variants.ts`. Контрактный тест сравнивает строки,
область и примечания с действующим источником проекта и запрещает
добавлять складские поля или source URL. Публичных ссылок на источники нет.
После изменения исходного ряда снимок нужно пересоздать.

## Проверка и найденные ошибки

Независимая проверка закупочного сценария выявила и помогла исправить:
старую карточку 108×4 после переключения матрицы на D5; сохранённую
горизонтальную прокрутку, скрывавшую тонкие стенки D5; отсутствие прямой
заявки в пустом результате; непринятие конечного «мм» при вставке.

Браузерные проверки на 320/390/1536 px: все три режима, единицы мм/mm,
знаки ×/х/x, десятичная запятая, точное совпадение D и s, отсутствие
сочетания, условия согласования, смена диаметра и сброс старой карточки,
каждая видимая кнопка матрицы против исходных пар, заполнение формы и
наличие поля файла. 41 проверка сценариев/контрактов прошла, ошибок JS нет.
JSON запрашивается один раз; режимы не вызывают новых запросов за размерами.
Снимки трёх вариантов на 390 и 1536 px просмотрены.

Без JS доступны ссылки прикрепления спецификации и полной основной
таблицы; интерактивное сравнение без JS не заявляется. При ошибке
загрузки данных оба запасных пути остаются доступными. Формы не отправлялись.

(HTML 2093, CSS 1913, JS 4072, данные 1032). Одна небольшая таблица данных,
без библиотек, внешних шрифтов и изображений. Это объём сжатых ресурсов,
не измерение LCP/INP или фактического сетевого transfer size.
Главная остаётся 12077 байт HTML gzip и один скрипт. Новые ресурсы
подключены только на странице сравнения.
