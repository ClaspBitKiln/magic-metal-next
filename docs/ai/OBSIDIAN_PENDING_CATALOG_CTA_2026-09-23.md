# Magic Metal — упрощение CTA каталога

## Решение

- Убраны десять повторяющихся кнопок «Заявка» в карточках каталога.
- Каждая карточка раздела стала одной доступной ссылкой на форму с выбранным направлением.
- В шапке каталога оставлена одна общая кнопка «Отправить заявку».
- В форме показывается выбранный раздел.
- Текст формы уточняет самовывоз или доставку с городом и согласование возможной замены.
- Первый шаг формы упрощён: удалены повторные заголовки и постоянное сообщение об отсутствии файлов; оставлены одно действие загрузки, краткая подсказка, описание и продолжение.
- Мобильная шапка упрощена: на ширине до 480 px CTA сокращается до «Заявка», язык и меню имеют области нажатия минимум 44×44 px.
- Второй шаг формы сокращён до телефона, email, согласия и кнопок; имя, компания и повторный выбор направления удалены.
- Сквозной тест обнаружил `500` из-за обязательной зависимости маршрута от Payload/Postgres; сохранение, SMTP и CRM разделены на независимые каналы с явным `503`, только если не сработал ни один канал.
- Повторный тест локализовал корневую причину: статический импорт `payload.config` проверял `PAYLOAD_SECRET` и `DATABASE_URL` до запуска обработчика. Конфигурация Payload переведена на динамический импорт внутри защищённого канала сохранения; обработчики ошибок SMTP/CRM больше не зависят от недоступного `payload.logger`.
- Удалён жёстко записанный URL-токен Activepieces; интеграция теперь использует только защищённые переменные `N8N_WEBHOOK_URL` или `CRM_WEBHOOK_URL` в Vercel.
- Из полосы доставки удалён третий дублирующий CTA первого экрана.
- Добавлены видимые состояния клавиатурного фокуса для карточек и загрузки файла.

## Решение блокировки DNS 2026-09-28

- Публичный снимок зоны подтверждён через Cloudflare DNS: `A @ → 77.222.62.219`, TTL около 600 секунд.
- NS: `ns1.spaceweb.ru`, `ns2.spaceweb.ru`, `ns3.spaceweb.pro`, `ns4.spaceweb.pro`.
- MX: `10 mx.yandex.net.`.
- TXT корня: SPF `v=spf1 redirect=_spf.yandex.net`, две проверки Яндекса и одна проверка Google; эти записи сохраняются без изменений.
- `https://www.magicmet.ru/` сейчас доступен на старом сервере и отвечает редиректом на `https://magicmet.ru/`; при откате созданный CNAME `www` нужно удалить, чтобы восстановить прежнее поведение зоны.
- Официальный API SpaceWeb: авторизация через `POST https://api.sweb.ru/notAuthorized/`, метод `getToken`; DNS — `POST https://api.sweb.ru/domains/dns`.
- Перед изменением API должен выполнить `info` и `getFile`, затем только `editMain` для индексов корневой A-записи и `www`; методы `editMx`, `editTxt`, `editNS`, `editSrv` не использовать.
- API не является обходом авторизации: нужен логин/пароль панели SpaceWeb либо существующий Bearer-токен.
- Самый быстрый немутирующий путь — вернуть онлайн Windows-мост `DESKTOP-BNPIVK2` и использовать ранее авторизованную локальную сессию/менеджер паролей.
- Альтернатива — восстановление доступа по административному email SpaceWeb: первое письмо позволяет определить логин; новый пароль выдаётся только после перехода по ссылке.
- Регистратор домена — RU-CENTER-RU; резервный путь через перевод на прямое обслуживание существует, но требует анкеты/документов и не нужен для обычной замены двух записей.
- Точный откат: `A @ → 77.222.62.219`, удалить созданный `CNAME www`; NS/MX/TXT не менять; старый хостинг держать доступным 24–48 часов.

## Следующие действия

- Получить доступ к панели Spaceweb и заменить только web-записи `@` и `www`, не меняя NS, MX и TXT.
- После распространения DNS проверить HTTPS, `magicmet.ru`, `www.magicmet.ru`, мобильную форму и резервный email-канал.
- После переключения DNS повторно проверить автоматическую отправку с `magicmet.ru`; текущий критерий готовности уже выполнен на Vercel: HTTP `200`, `emailDelivered: true`.
- Сохранить опубликованный email-fallback как резервный канал.
