## Подтверждённая причина сдвига

`layout.tsx` намеренно загружает общий `site.css` через `media=print`
с последующим переключением на `all`. Начальные стили `critical.css`
не содержали утверждённую шкалу заголовков и базовый сброс их отступов.

При контролируемой задержке общего CSS на ширине 412 px:

- Категория: h1 сначала 43,26 px / 700 / margin 28,98 px, затем
  35,02 px / 600 / margin 0. Начало следующего раздела сдвигалось
  с 508,67 до 454,52 px.
- Карточка: h1 сначала 43 px / 700 / margin 28,81 px, затем
  35,02 px / 600 / margin 0; менялась высота заголовка.

В `critical.css` перенесены существующие правила типографики из
`styles.css`, включая мобильную шкалу и компактные заголовки фактов.
Итоговый дизайн сохраняется. Контрольная HTML-подстановка этих же
начальных правил показала совпадение геометрии обоих маршрутов до
и после загрузки общего CSS. Клиентский JavaScript не добавляется.

Production-сборка и линтер прошли. Проверка готовой сборки с задержанным
`site.css` также прошла: координаты, высота, размер, жирность и отступы h1
совпадают до и после его загрузки на обоих маршрутах. SHA-256 главной
не изменился: `355e7ea74eca4ef688e758294ce019bddc0b8348c592900449067c484070b0d5`.
Повторный Lighthouse выполняется после развёртывания этой правки.

## Доверие сертификату при замере

Браузер использует предоставленный средой CA в собственном одноразовом
профиле `/tmp/magic-lh-browser-profile-20261015`, не в домашней NSS-базе.
Формат профильного импорта проверен по исходникам точной версии Chromium:
`components/server_certificate_database/server_certificate_database.proto`
и `chrome/browser/ui/webui/certificate_manager/user_cert_sources.cc`.
Схема и записи эквивалентны импорту доверенного CA через менеджер
сертификатов. Проверки цепочки, срока действия и имени сервера сохранены;
TLS-игноры и SPKI-исключения не применялись. Прямая проверка получила
HTTP 200 и TLS 1.3 для `magicmet.ru`.

Raw HTML/JSON отчёты, trace и сводка сохранены вне репозитория:
`/workspace/.cloud/magic-metal/performance-2026-10-15/`.
Временный исполнитель: `/tmp/magic-lighthouse-mobile.mjs`.
Для повторного замера нужен тот же доверенный CA профиля и Lighthouse
13.5.0; API-ключи и секреты в отчёт и код не записываются.

## Контролируемое сравнение влияния размерной таблицы

Для отделения кода от облачной доставки сохранены HTML обеих версий
и соответствующие исходные ресурсы. Старые два JS-чанка получены с
успешного неизменяемого развёртывания 2456064; остальные URL совпадают.
Обе версии воспроизводились одним локальным HTTP-сервером с gzip.
Сервер задерживал каждый ответ на 150 мс и выдавал тела через общую
очередь: 2048 байт каждые 10 мс, номинально 204800 байт/с.
Chromium использовал экран 412×823, DPR 1,75 и замедление CPU ×4.
Для каждого прогона создавался новый контекст с отключённым HTTP-кешем.
Предзагрузка переходов Next блокировалась одинаково у обеих версий,
чтобы сравнить начальную отрисовку страницы. Формы не отправлялись.

Порядок: до / после / после / до / до / после. Параллельных сборок
и других браузерных проверок во время замера не было.

| Версия | LCP трёх прогонов | Медиана LCP | Медиана TTFB | CLS |
| --- | --- | ---: | ---: | ---: |
| До | 412 / 368 / 420 мс | 412 мс | 161 мс | 0 во всех |
| После | 396 / 380 / 348 мс | 380 мс | 160 мс | 0 во всех |

В каждом прогоне LCP — заголовок h1; проверены 65 / 120 строк,
отсутствие ошибок JavaScript, неожиданных запросов и переполнения экрана.
Сжатый HTML передавался полностью: 16696 / 20173 байта без заголовков.
Объём остальных ресурсов одинаковый. Проверка задержки TTFB встроена
в исполнитель: замер без фактически применённого ограничения не проходит.
Предварительный прогон с CDP-ограничением сети не обеспечил задержку
на локальном соединении; он исключён из этого сравнения, сохранён
как `unthrottled-probe.json` и не считается мобильным замером.

Ухудшение LCP на 1,3 с из одиночной пары Lighthouse здесь не воспроизвелось.
В исходной паре Lighthouse оценил максимальную задержку сервера для
ресурсов в 528 / 977 мс; задержки изменились и у неизменённых JS/CSS.
Кроме того, он учёл у документа только 95 / 72 байта transferSize при
86238 / 114462 байтах распакованного HTML. Поэтому эти прогоны через
прокси не изолируют влияние таблицы на моделируемый LCP.

Сравнение не доказывает ускорение и не заменяет проверку доставки
посетителям из РФ. Оно не выявило регрессию начальной отрисовки от
добавления таблицы в заданных условиях; оснований откатывать размерный
ряд по этому результату нет. Исходные плохие Lighthouse-результаты выше
сохранены. Поведение сайта в этой проверке не менялось.
