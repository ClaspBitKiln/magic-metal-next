# Надёжность проверок сайта — 31 октября 2026

Восстановленный GitHub API дал доступ к фактическим CI-результатам. Последний
Vercel deployment a6f55b5 имеет success; проверка ссылок каталога прошла.
Это не означало успешный Site QA или Firefox: оба workflow завершились failure.

## Выявленные причины

- Performance QA ждал networkidle и падал через30секунд. Для снимка
  navigation load теперь ожидается событие load. Отложенная аналитика может
  продолжать работу; выборка ресурсов на load не является полным сетевым
  объёмом страницы или полевой метрикой. Изменение метода не ускоряет сам сайт.
- Accessibility heuristic проверял innerText и пропускал обычные связанные
  label/aria-labelledby/altизображений. Теперь используются штатные Playwright
  accessible-name selectors; дляfileinputs учитываются подписи и title.
- Visual heuristic считал scrollHeight>clientHeight обрезкой даже при visible
  overflow. Теперь требуется реально обрезающий hidden/clip; намеренная
  внутренняя прокрутка не приравнивается к потерянному тексту.
- Firefox в noJScontexts зависал на page-side Promise image.decode().
  Проверки изображений переведены на polling синхронных complete/naturalWidth;
  source/layout/resolution/negativeimage assertions и noJSрежим сохранены.

QA-правки не меняют UI, тексты, CSS, hero, #about или доставку заявок.
Регрессионные фикстуры проверяют корректные и отсутствующие подписи,
истинную и ложную обрезку и незавершающийся фоновый запрос.
Подробные результаты локальных и новых CI-проверок дополняются после выполнения;
предыдущие красные workflow не объявляются исправленными только по diff.

## Подключения

GitHub API доступен для чтения репозитория, workflow и deploymentстатусов.
Операция чтения repository secrets вернула403 Resource not accessible by integration.
Это не авторизация VercelAPI. В конфигурации среды подготовлено защищённое
требование VERCEL_TOKEN только для api.vercel.com. Сохранение драфта подтверждено,
requires_publish=true; значение ещё не подключено. Существующее подключение
Метрики не изменялось. Для проверки проекта Vercel и дальнейшей настройки CMS
нужны review/save/publish этой конфигурации и защищённый токен нужного проекта/team.
База, objectstorage и платные ресурсы этой работой не создавались.
